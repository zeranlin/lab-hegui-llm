## 1. 定位

本规则用于解决知识库变大后的精准调用问题。

后续知识点、风险审查点、法规依据和语料样本会越来越多，不能只靠关键词全文检索。标准审查应先通过文件画像确定项目标签，再按标签路由到对应知识。

```text
招标文件
  -> 文件画像标签
  -> 知识路由
  -> 品目动作化审查包 + 横向专题动作包
  -> 逐章审查矩阵
  -> 风险审查点
  -> 项目审查记录
```

核心原则：

- 目录不无限拆分，避免同一风险在全国、广东、深圳、物业、医院等目录重复复制。
- 元数据必须细分，用适用地域、采购方式、品目、场景、章节和状态控制召回。
- 文件画像是路由器，品目动作化审查包和横向专题动作包是调度器，风险审查点是最小规则单元。

## 2. 知识分层

### 2.1 通用规则

适用范围：全国政府采购通用规则。

典型内容：

- 不得以不合理条件限制或排斥供应商；
- 评审因素应当与采购需求和履约质量相关；
- 采购需求、评分、合同和验收应当清楚、完整、可执行；
- 政府采购政策、中小企业政策、节能环保政策等全国规则。

默认位置：

- `wiki/10-法规依据/`
- `wiki/20-知识点/`
- `wiki/25-风险审查点/`

### 2.2 地域规则

适用范围：某省、某市、某平台或某集中采购机构。

典型内容：

- 深圳经济特区政府采购规则；
- 深圳供应商信用信息规则；
- 地方集中采购目录、限额标准、平台操作规则；
- 某省或某市对投标材料、评定分离、信用信息、电子交易的特殊口径。

使用要求：

- 地域规则必须标注 `适用地域::` 和 `地域状态::`。
- 地方规则不能突破上位法禁止性规定。
- 平台规则只能作为操作和材料提交口径，不能单独创设限制供应商的实体条件。

### 2.3 采购方式规则

适用范围：公开招标、磋商、谈判、询价、框架协议、电子卖场等不同程序。

典型内容：

- 公开招标评分办法、资格审查、符合性审查；
- 框架协议入围、二阶段成交、淘汰比例；
- 竞争性磋商综合评分和磋商程序；
- 询价最低价和货物规格参数。

### 2.4 品目规则

适用范围：采购品目或标的属性。

典型内容：

- 物业管理服务；
- 信息化设备；
- 保安服务；
- 家具；
- 食材；
- 软件开发和系统集成。

品目规则应回答：

- 该品目常见章节有哪些；
- 哪些风险高频出现；
- 哪些资格、人员、证书、业绩和合同条款容易误判；
- 哪些风险只在该品目下高概率成立。

### 2.5 场景规则

适用范围：品目下的细分业务场景。

典型内容：

- 学校物业；
- 医院物业；
- 建筑机电物业；
- 法院和机关物业；
- 信息化系统集成；
- 数据中心、等保、密评、运维服务。

场景规则主要用于缩小判断边界。比如医院物业可以要求特殊岗位、感染控制、应急保障；但不能把性别比例、就近住宿、本地设点等要求当然合理化。

### 2.6 项目经验

适用范围：具体项目复盘中的漏报、误报和人工调整。

默认位置：

- `wiki/40-审查工作台/人工调整复盘/`
- `wiki/40-审查工作台/知识更新申请/`

项目经验不能直接变成稳定审查规则。必须经过复盘、知识更新申请和回写后，才能进入通用规则、地域规则、品目规则或场景规则。

### 2.7 横向专题规则

适用范围：跨品目、跨场景、跨章节反复出现的审查维度。

典型内容：

- 技术要求合规性审查，包括技术参数、标准引用、检测报告、样品、重要参数、证明材料；
- 评分办法审查，包括方案评分、业绩评分、财务评分、认证评分、人员证书评分；
- 合同和验收审查，包括付款、验收、违约、模板错配、专用条款缺失；
- 政府采购政策审查，包括中小企业、绿色采购、节能环保、进口产品。

横向专题规则主要解决“只按品目路由会漏掉跨品目问题”的情况。例如家具文件不仅要调用家具采购动作包，还要在技术参数、`▲`、`★`、标准号、检测报告、样品要求出现时，同时调用 [[wiki/20-知识点/技术要求合规性审查方法]] 和 [[wiki/70-审查协议/技术要求合规性审查动作协议]]。

横向专题规则不替代品目规则。正确调用方式是叠加：

```text
品目规则
  + 横向专题规则
  + 章节规则
  + 质量门
```

## 3. 标准元数据

新增或改造知识点、风险审查点时，顶部必须尽量包含以下字段：

```text
类型::
状态::
主题::
知识层级::
审查点类型::
风险类型::
默认等级::
效力层级::
适用地域::
地域状态::
适用采购方式::
适用品目::
适用场景::
适用章节::
触发信号::
排除条件::
优先级::
复核角色::
关联法规::
关联知识点::
关联动作包::
```

字段说明：

| 字段 | 作用 |
| --- | --- |
| 知识层级 | 判断是通用、地域、方式、品目、场景还是项目经验 |
| 审查点类型 | 控制风险审查点在路由中的类别 |
| 效力层级 | 判断依据来源的层级 |
| 适用地域 | 控制全国、省、市、平台差异 |
| 地域状态 | 控制地域有效、地域待核、地域冲突或地域废止 |
| 适用采购方式 | 控制公开招标、磋商、框架协议等差异 |
| 适用品目 | 控制品类调用 |
| 适用场景 | 控制医院、学校、建筑机电等细分场景 |
| 适用章节 | 控制逐章审查召回 |
| 触发信号 | 给 AI 的第一轮召回线索 |
| 排除条件 | 降低误报的边界 |
| 复核角色 | 明确谁有权把待核规则升为有效 |

## 4. 路由顺序

收到新文件后，按以下顺序调用知识：

```text
1. 全国通用政府采购规则
2. 项目所在地规则
3. 采购方式规则
4. 标的属性规则
5. 采购品目规则
6. 细分场景规则
7. 招标文件章节规则
8. 横向专题规则
9. 项目复盘中试运行规则
```

冲突处理：

```text
上位法禁止性规则
  > 地方补充规则
  > 平台操作规则
  > 品类经验规则
  > 项目复盘经验
```

无法判断冲突时，项目审查记录中标记“需人工复核”，不得直接输出确定性结论。

## 5. 画像标签到知识调用

### 5.1 地域路由

| 画像标签 | 必调知识 |
| --- | --- |
| 地域=全国或地域不明 | 国家政府采购法律、行政法规、财政部规章和通用风险审查点 |
| 地域=广东省 | 全国通用规则；广东省规则待扩展 |
| 地域=深圳市 | 全国通用规则；深圳经济特区政府采购规则；深圳供应商信用和平台规则 |
| 平台=深圳公共资源交易中心或深圳智慧采购平台 | 深圳平台相关证明材料、信用信息、电子投标和评定分离规则 |

### 5.2 采购方式路由

| 画像标签 | 必调知识 |
| --- | --- |
| 采购方式=公开招标 | 87号令；资格性审查；符合性审查；综合评分或最低价规则 |
| 采购方式=竞争性磋商 | 磋商文件结构、综合评分、磋商程序和实质性响应规则 |
| 采购方式=框架协议 | 框架协议采购规则、入围和成交机制、淘汰比例和二阶段成交规则 |

### 5.3 品目和场景路由

| 场景=建筑机电物业 | 机电人员证书、特种作业持证、方案评分高占比、近场响应和就近住宿 |

### 5.4 章节路由

| 章节标签 | 必调审查点 |
| --- | --- |
| 招标公告 | 资格条件、采购方式、预算、联合体、进口产品、中小企业政策 |
| 资格性审查表 | 资格条件违法或过度、证明材料要求不清、分公司授权和关联主体限制 |
| 符合性审查表 | 投标无效扩大化、实质性条款设置过多或不清 |
| 采购需求 | 需求完整性、技术参数指向性、人员限制、响应时限、品目和所属行业 |
| 评分办法 | 评审因素脱节、人员证书、认证、业绩、荣誉、方案主观分、财务评分、本地化 |
| 合同条款 | 合同模板错配、付款不明确、验收不可操作、违约责任过重 |

## 6. 风险审查点分类

风险审查点保持在 `wiki/25-风险审查点/`，但通过元数据分为五类：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 全国通用审查点 | 全国政府采购项目均可能适用 | 资格条件违法或过度；评分因素与采购需求脱节 |
| 地域专用审查点 | 只适用于某省、市或平台 | 深圳信用信息评分规则；深圳平台材料规则 |
| 品目专用审查点 | 只在某类采购品目中高频适用 | 物业人员年龄性别限制；信息化设备制造商授权；家具检测报告和环保认证范围特定化 |
| 场景专用审查点 | 品目下特定场景适用 | 医院物业女性保安比例；建筑机电15分钟到场 |
| 缺失类审查点 | 应写未写或结构不完整 | 预算缺失；所属行业缺失；付款验收空白 |

## 7. 知识回写路由

复盘发现新问题时，按以下路径回写：

| 发现类型 | 回写位置 |
| --- | --- |
| 新法规或新政策 | `wiki/10-法规依据/` |
| 新地域口径 | `wiki/10-法规依据/` 或地域规则页，状态先标 `地域待核` |
| 新品目或新场景 | `wiki/15-行业基础/` 和对应动作化审查包 |
| 新判断规则 | `wiki/25-风险审查点/` |
| 新跨品类风险模式 | `wiki/30-风险库/` |
| 新原文样本 | `wiki/50-语料与摘录/` |
| 新输出格式要求 | `wiki/90-模板/` 或 `wiki/60-提示词/` |
