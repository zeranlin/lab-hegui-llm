# 审查精确率提升流程

类型:: 知识点
状态:: 有效
主题:: 审后复盘
适用阶段:: AI 审查完成后
关联知识点:: [[wiki/00-入口/审查动作系统]]; [[wiki/20-知识点/政府采购逐章审查矩阵]]

## 定位

本流程用于 AI 审查完成后提升后续审查精确率。它不是项目审查记录的一部分，也不生成第二套项目审查记录。

产物应当是复盘记录、知识库补强和提示词优化。

## 输入

- 已完成的项目 AI 审查记录；
- 原始招标文件和抽取文本；
- 人工复核意见、专家意见、质疑投诉结果或外部标注；
- 审查过程中发现的漏报、误报和表述不清。

## 输出

- 漏报清单；
- 误报清单；
- 风险审查点补强；
- 逐章审查矩阵补强；
- 典型原文样本补强；
- 提示词和模板优化；
- 下一轮 AI 审查注意事项。

## 流程

### 1. 对齐口径

先确认复盘对象：

- 是否同一份招标文件；
- 行号口径是否一致；
- 风险粒度是原子风险还是合并风险；
- 哪些只是优化建议，哪些属于正式风险；
- 外部意见是否有法规依据或审查规则支撑。

### 2. 漏报归因

对每个漏报判断原因：

| 漏报原因 | 处理方式 |
| --- | --- |
| 知识库没有对应审查点 | 新增或补强 `wiki/25-风险审查点/` |
| 审查点有，但识别信号不足 | 补充典型原文、关键词、反向表达和章节位置 |
| 逐章流程没覆盖 | 更新 [[wiki/20-知识点/政府采购逐章审查矩阵]] |
| 需要缺失类判断 | 更新 [[wiki/20-知识点/缺失类风险审查]] |
| 场景知识不足 | 更新 [[wiki/15-行业基础/政府采购专项场景画像]] |
| 提示词没有要求原子化 | 更新 `wiki/60-提示词/` |

### 3. 误报归因

对每个误报判断原因：

- 是否把弱信号当成确定风险；
- 是否忽略了项目场景必要性；
- 是否忽略了其他章节已有补充说明；
- 是否没有设置排除条件；
- 是否法规依据不足。

误报处理优先补充风险审查点中的“排除条件”和“常见误报”。

### 4. 知识库回写

复盘发现的问题应回写到稳定知识层：

- 共性规则 -> `20-知识点/`
- 原子风险规则 -> `25-风险审查点/`
- 典型风险模式 -> `30-风险库/`
- 原文样本 -> `50-语料与摘录/`
- 操作流程 -> `60-提示词/`

不要只修改单个项目审查记录。

### 5. 下一轮验证

知识库补强后，下一份文件仍按 AI 审查方式处理。只有 AI 审查结果能反映知识库和提示词的真实审查能力。

```text
## 知识库更新

- 审查点：

```
