## 1. 定位

本页是跨品目的技术要求审查方法。它不替代家具、医疗设备、信息化设备、车辆等品目动作包，而是在文件出现技术参数、`▲`、`★`、检测报告、样品、标准号、现行标准、强制标准等信号时叠加调用。

核心判断不是“参数是否高级”，而是每个技术要求是否同时具备：

- 采购需求依据；
- 适用标准依据；
- 竞争中立性；
- 可验证路径；
- 合理阶段边界。

任一维度明显缺失，进入风险候选。

## 2. 五维判断框架

### 2.1 采购需求依据

审查问题：

- 该参数是否服务于采购目标、使用场景、安全、环保、耐用性、兼容性或验收需要；
- 是否把非核心、非必要、装饰性、外观性、个别结构细节写成实质性要求；
- 是否用“采购人习惯”“既有图纸”“现有品牌规格”替代公开竞争需求。

输出口径：与功能、安全、质量、验收无直接关系的精细参数，应提示可能形成特定产品画像。

### 2.2 适用标准依据

审查问题：

- 引用标准号、年份、名称是否准确；
- 标准是否现行；
- 标准适用品类是否匹配；
- 指标是否来自对应标准，是否被跨材料、跨产品、跨检测方法套用；
- 强制标准是否遗漏，推荐标准是否被当作唯一强制门槛。

输出口径：标准引用错误、适用对象不匹配、旧标准沿用或现行强制标准缺失，应列为风险或需人工复核。

### 2.3 竞争中立性

审查问题：

- 多个参数、检测对象、检测结果、样品结构和证明材料是否组合成特定供应商或既有产品画像；
- 是否只允许一种技术路线、工艺路线、材料组合或检测报告组合；
- 是否把投标人或制造商既有检测报告作为投标门槛。

输出口径：如果不同合格技术路线被不必要排除，应按“指向性参数”“检测报告前置”“样品结构过细”等风险原子输出。

### 2.4 可验证路径

审查问题：

- 指标是否有明确检测方法、限值、检出限、试验条件和验收资料；
- “未检出”“优质”“高级”“环保”“抗菌”等表述是否可复核；
- 样品、检测报告、承诺函、验收检测之间的证明关系是否清楚。

输出口径：不能客观验证、不同实验室不可比或检出限不明的指标，应改为国家标准限值、明确数值和检测方法。

### 2.5 合理阶段边界

审查问题：

- 哪些材料适合投标阶段承诺响应；
- 哪些适合中标后深化、供货前确认；
- 哪些适合到货验收或抽检；
- 投标阶段是否要求大量全项检测报告、样品照片、实验过程照片、样品接收证明等。

输出口径：投标阶段证明负担过重、实际只能由既有供应商满足时，应提示调整到中标后或验收阶段。

## 3. 高频触发信号

| 信号 | 必须反查 |
| --- | --- |
| `▲`、`★`、实质性参数、不得负偏离 | 是否把非核心技术要求设为实质性响应 |
| 检测报告、CMA、CNAS、委托单位、样品照片、实验过程照片 | 是否形成前置检测报告门槛 |
| GB、GB/T、HJ、QB/T、ISO、EN | 标准号、年份、名称、适用对象和现行状态 |
| HCI/HCl、贡/汞、NSS/ASS、单位、上下限、区间表达 | 技术术语和专业文字错误是否影响响应、检测和验收 |
| 未检出、检出限、苯、甲醛、VOC、重金属 | 是否与检测方法、限值和检出限匹配 |
| 抗菌、抗病毒、特殊菌种 | 是否有使用场景和标准依据，是否检测项目堆叠 |
| 精确尺寸、角度、结构、接口位置、部件形状 | 是否疑似既有产品图纸 |
| 后期深化、中标后深化、根据采购人需求深化 | 是否影响投标响应、评分和合同履约边界 |

## 4. 输出规则

技术要求风险应尽量保持“原文参数 + 判断问题 + 阶段建议”的结构：

```text
标题：对象 + 异常技术要求 + 风险类型
原文内容：只放文件原文参数或缺失事实
问题说明：说明标准、竞争、验证或阶段边界问题
修改建议：给出投标阶段、中标后、验收阶段的替代路径
```

## 5. 与品目包的关系

技术要求专题与品目动作包叠加使用：

- 家具项目：叠加 [[wiki/20-知识点/家具技术要求专项审查包]] 和 [[wiki/20-知识点/家具采购动作化审查包]]。
- 医疗设备：叠加医疗器械注册、参数指向、耗材维保、质保培训等品目规则。
- 信息化设备：叠加兼容性、软件著作权、等保密评、数据接口和运维边界。
- 车辆：叠加公告目录、上牌、排放、改装一致性和费用边界。

先用本页判断“技术要求是否合规”，再用对应品目包判断“该品目下是否合理”。
