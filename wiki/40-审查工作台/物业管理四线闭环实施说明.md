## 1. 定位

本说明把“政府采购行业物业管理招标文件合规性审查”样板中的四条线落成可执行流程。

物业管理样板不是只保存 5 份项目审查记录，而是在“一个可由 AI 调度执行的政府采购行业招标文件审查动作型知识系统”下，形成可持续工作的品类闭环：

```text
第一条线：政府采购物业管理招标文件知识生成管理
  -> 第二条线：政府采购物业管理招标文件 AI 审查主流程
  -> 第三条线：政府采购物业管理招标文件人工调整和精确率提升
  -> 回到第一条线：更新物业管理招标文件审查知识

第四条线：外部执行主体读取物业知识并复现 AI 审查主流程
```

四条线各自解决不同问题：

| 线 | 解决的问题 | 主要产物 |
| --- | --- | --- |
| 知识生成管理线 | 政府采购物业管理招标文件审查要用哪些知识，哪些知识可用，谁能改 | 场景画像、动作包、风险审查点、语料样本、知识更新申请 |
| AI 审查主流程线 | 新的政府采购物业管理招标文件来了怎么审，风险怎么输出 | 文件画像、逐章审查、项目 AI 审查记录 |
| 人工调整和精确率提升线 | 审查人员如何改结果，如何把漏报误报变成知识 | 人工调整复盘、知识更新申请、回写记录 |
| 外部执行主体使用线 | 外部 AI Agent、自动化执行器或人工助理如何读取物业知识并复现审查动作 | 外部执行主体审查指引、动作清单、运行记录、质量门结果 |

## 2. 总目标

物业管理样板的目标是让下一份政府采购物业管理招标文件进入后，系统能够稳定完成以下动作：

1. 先识别它是不是物业管理项目，以及属于学校、医院、法院机关、建筑机电或一般物业中的哪类场景。
2. 自动调用物业管理动作化审查包，而不是只靠全文搜索关键词。
3. 按章节查招标公告、资格条件、用户需求书、人员配置、评分办法、证明材料和合同条款。
4. 对存在问题的原文形成风险点，对应写未写的内容形成缺失类风险。
5. 每个风险点都能反链到稳定风险审查点、法规依据或知识点。
6. 审查人员调整结果后，能判断是项目个案，还是需要更新物业管理招标文件审查知识。

需要注意的是，当前样板不是 raw 目录自动监听式审查。新文件放入 raw 后，仍需 AI 按本实施说明调度执行抽取、画像、审查和记录生成。

## 3. 第一条线：政府采购物业管理招标文件知识生成管理

### 3.1 这条线管什么

这条线管理“政府采购物业管理招标文件合规审查系统知道什么”。

它不处理某个项目的最终审查结论，而是负责把可复用内容变成稳定知识，包括：

- 物业管理服务采购背景；
- 学校、医院、法院机关、建筑机电等场景画像；
- 物业管理招标文件逐章审查动作；
- 高频风险审查点；
- 典型原文样本和边界样本；
- 审查提示词和输出模板；
- 人工复盘后形成的知识更新申请。

### 3.3 知识进入规则

物业管理招标文件审查知识进入稳定层前，必须先判断它属于哪一类：

| 来源 | 先放哪里 | 什么时候能回写稳定知识 |
| --- | --- | --- |
| 法规和政策 | `wiki/10-法规依据/` | 确认来源、效力层级和适用地域后 |
| 物业行业背景 | `wiki/15-行业基础/` | 能影响场景画像或审查重点时 |
| 审查动作 | `wiki/20-知识点/` | 能回答看哪里、找什么、怎么判断时 |
| 风险规则 | `wiki/25-风险审查点/` | 有原文样本、判断规则和排除条件时 |
| 项目经验 | `wiki/40-审查工作台/人工调整复盘/物业管理/` | 经复盘确认可复用后 |
| 典型条款 | `wiki/50-语料与摘录/` | 能作为正例、反例或边界样本时 |

单个项目里的临时判断不能直接写成有效规则。必须先进入人工调整复盘或知识更新申请，再决定是否回写。

### 3.4 物业管理审查知识状态

物业管理招标文件审查知识至少分五种状态：

| 状态 | 使用方式 |
| --- | --- |
| 草稿 | 只供整理，不驱动正式审查 |
| 待复核 | 可提示，但风险结论需标记需人工确认 |
| 试运行 | 可用于 AI 审查，但要观察漏报和误报 |
| 有效 | 可作为正式审查依据 |
| 废止 | 不再用于审查 |

当前 [[wiki/20-知识点/物业管理动作化审查包]] 状态为 `试运行`。因此它可以驱动物业 AI 审查，但高风险结论仍应由审查人员复核。

### 3.5 权限和角色

| 角色 | 在物业样板中的权限 |
| --- | --- |
| 知识维护人 | 整理物业原文样本、补充动作卡草稿、维护索引 |
| 业务审查人 | 使用物业动作包审查项目，提出人工调整和知识更新申请 |
| 品类复核人 | 判断物业专项规则是否可从试运行升为有效 |
| 法规复核人 | 判断上位法、深圳地方规则和平台口径是否支持风险结论 |
| 系统维护人 | 维护模板、lint、目录和命令，不替代业务判断 |

## 4. 第二条线：政府采购物业管理招标文件 AI 审查主流程

### 4.1 这条线管什么

这条线管理“新的政府采购物业管理招标文件来了怎么审”。

它输出项目 AI 审查记录，不直接修改稳定知识。

### 4.2 输入和输出

| 环节 | 输入 | 输出位置 |
| --- | --- | --- |
| 原始文件入库 | `raw/招标文件/物业管理/` 下的 Word、PDF 等原件 | 不编辑原件 |
| 文本抽取 | 原始招标文件 | `raw/抽取文本/物业管理/` |
| 来源笔记 | 原文和抽取文本 | `wiki/50-语料与摘录/` |
| 文件画像 | 抽取文本、来源笔记、画像规则 | 审查记录中的“文件画像” |
| 逐章审查 | 招标公告、资格、需求、评分、合同等章节 | 风险点清单和待确认事项 |
| 风险输出 | 原文证据、审查点、依据和建议 | `wiki/40-审查工作台/审查记录/物业管理/` |
| 运行记录 | AI 调度轮次、工具调用、读取原文范围、产物路径 | `wiki/40-审查工作台/运行记录/物业管理/` |

### 4.3 标准审查动作

每份政府采购物业管理招标文件必须按以下顺序审：

1. 建立文件身份画像：项目名称、编号、采购人、预算、采购方式、评审方法。
2. 建立制度画像：是否深圳项目、是否公开招标、是否综合评分、是否专门面向中小企业。
3. 建立物业场景画像：学校物业、医院物业、法院机关物业、建筑机电物业或一般物业。
4. 调用物业动作包：使用 11 张动作卡逐章检查。
5. 抽取原文证据：风险点的 `原文内容` 只放招标文件原文。
6. 判断风险：在 `问题说明` 中写判断理由，不混入原文内容字段。
7. 反链审查点：每个风险点至少关联一个 `wiki/25-风险审查点/`。
8. 输出修改建议：给出可落地的修改方向。
9. 形成运行记录：使用 [[wiki/90-模板/AI调度运行记录模板]] 记录本次 AI 调度过程。

### 4.4 物业管理招标文件必查章节

| 章节 | 必查内容 | 常见风险 |
| --- | --- | --- |
| 招标公告 | 预算、采购方式、资格、联合体、中小企业政策 | 资格条件过度、所属行业缺失、联合体边界不清 |
| 资格性审查 | 法定资格、特定资格、分公司授权 | 非法资格、分公司授权路径过窄 |
| 符合性审查 | 投标无效、星号条款、承诺函 | 无效条款扩大化、实质性要求过多 |
| 用户需求书 | 服务范围、人员配置、岗位条件、响应、验收 | 年龄性别形象限制、响应时限过短、需求不明确 |
| 评分办法 | 方案、人员、业绩、认证、荣誉、本地化 | 主观分档、证书堆叠、业绩过窄、本地化 |
| 证明材料 | 社保、官网截图、原件备查、合同关键页 | 材料要求过度、线下核验冲突 |
| 合同条款 | 付款、验收、违约、服务期、费用边界 | 关键空白、模板错配、付款验收不清 |

### 4.5 风险输出口径

项目审查记录中的单个风险点建议固定为：

```text
### 风险编号. 风险标题

- 结论类型：
- 风险等级：
- 原文位置：
- 原文内容：
- 问题说明：
- 关联审查点：
- 审查依据：
- 修改建议：
```

字段边界必须清楚：

| 字段 | 写什么 | 不写什么 |
| --- | --- | --- |
| 原文内容 | 招标文件中直接摘录的原文 | 不写解释、不写推理、不改写 |
| 问题说明 | 为什么该原文构成风险或需复核 | 不替代原文 |
| 关联审查点 | 稳定风险规则链接 | 不写成泛泛分类 |
| 修改建议 | 采购文件如何改 | 不只写“建议完善” |

### 4.6 项目记录质量门槛

物业 AI 审查记录交付前，应满足：

- 预算金额和项目名称核对无误；
- 文件画像能说明为什么调用物业动作包；
- 风险点数量和正文编号一致；
- 每个风险点都有原文内容；
- 每个风险点都有问题说明；
- 每个风险点至少关联一个风险审查点；
- 缺失类风险说明应有内容和未见内容；
- 不确定事项放入待确认，不强行定性。

## 5. 第三条线：政府采购物业管理招标文件人工调整和精确率提升

### 5.1 这条线管什么

这条线管理“审查人员改了 AI 结果之后，系统怎么变得更准”。

人工调整不能直接污染项目 AI 审查记录，也不能直接把个案写成有效知识。应先形成复盘，再判断是否进入知识更新申请。

### 5.2 人工调整类型

| 调整类型 | 物业场景示例 | 后续动作 |
| --- | --- | --- |
| 补充漏报 | 需求书存在女性保安比例、就近住宿、年龄形象限制但 AI 未识别 | 生成知识更新申请，补触发信号 |
| 删除误报 | 文件仅不接受联合体，但无多专业分包风险 | 补排除条件和常见误报 |
| 修改风险等级 | 风险成立但高低判断不准 | 补等级判断口径 |
| 修改标题 | 风险成立但标题不像审查意见 | 更新输出口径 |
| 修改原文定位 | 找到了风险但摘录不是最直接原文 | 补语料样本和抽取要求 |
| 修改建议 | 建议太空，不适合采购人修改文件 | 补推荐修改方向 |
| 项目特殊判断 | 法院保密、医院感染控制等特殊履约要求 | 只在项目记录备注，必要时补排除条件 |

### 5.3 复盘分流规则

人工调整后按以下规则分流：

```text
人工调整事项
  -> 是否影响同类物业文件？
    -> 否：作为项目个案备注
    -> 是：进入人工调整复盘
      -> 是否已有风险审查点？
        -> 有：补识别信号、判断规则或排除条件
        -> 无：申请新增风险审查点
      -> 是否影响逐章审查？
        -> 是：更新物业动作包或逐章矩阵
      -> 是否影响输出结构？
        -> 是：更新模板或提示词
```

### 5.4 回写位置

| 复盘发现 | 回写位置 |
| --- | --- |
| 场景画像不够 | [[wiki/15-行业基础/物业管理服务采购背景]]; [[wiki/15-行业基础/政府采购专项场景画像]] |
| 审查动作漏项 | [[wiki/20-知识点/物业管理动作化审查包]] |
| 章节调度漏项 | [[wiki/20-知识点/政府采购逐章审查矩阵]] |
| 风险规则缺失 | `wiki/25-风险审查点/` |
| 误报边界不清 | 对应风险审查点的排除条件和常见误报 |
| 原文摘录不准 | `wiki/50-语料与摘录/` |
| 提示词约束不足 | `wiki/60-提示词/` |
| 审查记录不便于人工查看 | `wiki/90-模板/审查记录模板.md` |

### 5.5 当前 5 份物业样板已经形成的回写主题

| 回写主题 | 来源场景 | 当前去向 |
| --- | --- | --- |

| 近场响应和就近住宿 | 建筑机电物业 | 已补入本地化和响应时限审查点 |

## 6. 第四条线：外部执行主体使用

### 6.1 这条线管什么

这条线管理“外部执行主体如何使用物业管理审查知识”。

外部执行主体收到一份新的物业管理招标文件后，不应只检索风险关键词，而应按 [[wiki/00-入口/外部执行主体招标文件审查指引]] 和 [[wiki/70-审查协议/知识驱动审查执行规范]] 初始化审查。

### 6.2 物业场景必须读取的知识

外部执行主体命中物业管理画像后，至少读取：

- [[wiki/15-行业基础/物业管理服务采购背景]]
- [[wiki/20-知识点/物业管理动作化审查包]]
- [[wiki/70-审查协议/物业管理审查动作协议]]
- [[wiki/70-审查协议/风险原子化规则]]
- [[wiki/70-审查协议/质量门规则]]
- [[wiki/90-模板/审查记录模板]]
- [[wiki/90-模板/AI调度运行记录模板]]

### 6.3 物业场景必须复现的动作

外部执行主体应至少复现：

- 建立物业管理文件画像，识别学校、医院、法院机关、建筑机电或一般物业场景；
- 生成 `PROP-A01` 至 `PROP-A23` 动作清单；
- 按招标公告、资格条件、用户需求书、评分办法、证明材料和合同条款逐章审查；
- 对每个动作标记命中、未命中或待确认；
- 将命中问题拆成原子风险；
- 输出 AI 审查记录和运行记录；
- 输出质量门结果，说明是否存在未查章节、未执行动作或缺少原文证据的风险点。

外部执行主体如果只输出少量风险点，但没有物业画像、动作状态、质量门和运行记录，应视为没有完整使用物业管理知识系统。

## 7. 四条线如何衔接

### 7.1 正向流转

```text
物业知识生成管理
  -> 形成物业动作包、风险审查点、场景画像、模板和提示词
  -> 支撑新的政府采购物业管理招标文件 AI 审查
  -> 生成项目 AI 审查记录
  -> 交给业务审查人员复核
  -> 供外部执行主体读取并复现审查动作
```

### 7.2 反向回写

```text
业务审查人员调整结果
  -> 人工调整复盘
  -> 判断是否可复用
  -> 知识更新申请
  -> 复核后回写动作包、审查点、场景画像、语料或提示词
  -> 下一份政府采购物业管理招标文件验证效果
```

### 7.3 不能混用的边界

| 内容 | 能不能进入 AI 审查记录 | 正确位置 |
| --- | --- | --- |
| 本项目 raw 原文 | 可以 | 项目审查记录、来源笔记 |
| 本项目 wiki 知识 | 可以 | 项目审查记录引用 |
| 外部 V2 标准答案 | 不可以直接进入 | 审后复盘参考 |
| 人工批注意见 | 不可以冒充 AI 自审 | 人工调整复盘 |
| 个案判断 | 不直接进入稳定知识 | 项目备注或复盘 |
| 可复用漏报误报 | 不直接改成有效规则 | 知识更新申请后复核 |
