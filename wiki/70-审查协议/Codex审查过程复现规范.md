## 1. 定位

本文描述 Codex 在政府采购物业管理招标文件审查中，如何通过 LLM Wiki 查出较完整风险点的过程。

它不是某个执行器的开发任务，而是一套可复现的审查方法。任何外部执行主体只要读取本知识库，就应按本文的方法组织自己的审查流程。

## 2. 为什么能查出 20 个风险点

以西湾小学物业管理服务项目为例，Codex 能从早期较少风险扩展到 20 个风险，不是因为掌握了外部标准答案，而是因为执行了以下动作：

1. 先建立文件画像，确认这是深圳市、公开招标、服务类、物业管理、学校物业、综合评分法项目。
2. 按画像调用全国政府采购规则、深圳地方规则、物业管理动作化审查包、逐章矩阵和风险审查点。
3. 逐章读取公告、预算、服务需求、人员配置、评分办法、证明材料和合同。
4. 把评分办法拆成响应度、承诺函、人员、认证、资质、业绩、荣誉、软著等多个动作。
5. 把用户需求书拆成人员限制、校外服务边界、应急响应、付款和考核等动作。
6. 把合同拆成模板错配、付款空白、验收空白、违约空白和需求不一致等动作。
7. 对同一原文不做“一条大风险”处理，而是按原子化规则拆分。
8. 输出前用质量门反查人员、供应商能力、用户需求和合同漏项。

## 3. 标准复现流程

### 3.1 读取边界

标准 AI 审查只能使用：

- 本项目 `raw/` 中的原始文件；
- 本项目 `wiki/` 中的知识；
- 本项目 `tools/` 中的维护工具；
- 用户明确指定可使用的材料。

不得使用：

- 外部 V2 检查结果；
- 标准答案；
- 历史人工批注；
- 其他目录中的标注数据；
- 审查完成前的校准样本。

### 3.2 文件画像

先抽取：

- 项目编号；
- 项目名称；
- 采购人；
- 代理机构；
- 采购方式；
- 评审方法；
- 预算金额和分项预算；
- 采购品目；
- 标的所属行业；
- 是否专门面向中小企业；
- 是否接受联合体；
- 是否允许分包；
- 是否允许进口产品；
- 文件章节完整性。

画像结果决定后续调用哪些知识。

### 3.4 逐章读取

Codex 的关键动作不是一次性总结全文，而是按章节反复读取：

| 章节 | 读取目标 |
| --- | --- |
| 招标公告 | 资格、预算、政策、联合体、分公司 |
| 采购计划和服务需求明细 | 预算合计、标的名称、数量、单位、所属行业 |
| 政府采购政策 | 中小企业政策、声明函口径、价格扣除 |
| 资格和符合性 | 投标无效、星号条款、分公司、关联主体 |
| 用户需求书 | 服务范围、人员配置、年龄形象身份、校外边界、响应时限 |
| 评分办法 | 响应度、承诺函、人员、认证、资质、业绩、荣誉、软著 |
| 证明材料 | 学历、职称、职业资格、协会、社保、原件备查 |
| 合同条款 | 模板错配、付款、验收、违约、服务范围、保密 |

### 3.5 动作执行

物业管理项目必须执行 [[wiki/70-审查协议/物业管理审查动作协议]] 中的 `PROP-A01` 至 `PROP-A23`。

每个动作都要形成状态：

```text
命中：形成风险或待确认风险；
未命中：已读对应章节，未发现成立条件；
待确认：原文存在风险信号，但法律依据、地方口径或事实背景需要人工确认。
```

未命中动作也要记录，否则无法判断是“确实没有风险”还是“没有审查”。

## 4. 西湾小学样板的动作映射

以下映射说明 Codex 20 条风险如何来自动作协议：

| 动作ID | 动作名称 | 对应风险 |
| --- | --- | --- |
| PROP-A01 | 采购计划和预算完整性 | 第二采购计划仅列预算金额，未列明标的名称、数量、单位和所属行业 |
| PROP-A02 | 服务需求明细和所属行业 | 同上 |
| PROP-A03 | 中小企业政策和声明函口径 | 同上 |
| PROP-A04 | 资格条件和分公司授权 | 分公司投标只接受直接授权并排除逐级授权，关联主体同时投标无效边界较宽 |
| PROP-A06 | 响应度评分与基础响应重复 | 服务内容和人员配置响应度评分以偏离表响应给分，区分度不足 |
| PROP-A07 | 服务期满后过渡服务承诺 | 服务期满后仍按原合同提供服务作为承诺评分，过渡服务边界不清 |
| PROP-A08 | 违约承诺评分 | 违约承诺以承诺函固定给分，未形成可执行违约责任 |
| PROP-A09 | 项目负责人证书组合 | 项目负责人评分过度绑定多类证书组合 |
| PROP-A10 | 项目负责人社保时点 | 项目负责人社保证明限定开标日前一个月 |
| PROP-A11 | 服务团队证书组合 | 服务团队评分过度绑定学历、退伍身份、劳动关系协调员等证书 |
| PROP-A12 | 服务团队社保时点 | 服务团队社保证明同样限定开标日前一个月 |
| PROP-A13 | 证明材料和原件备查 | 人员评分证明材料要求多重查询截图并设置原件备查 |
| PROP-A14 | 体系认证范围 | 供应商体系认证限定认证范围包含物业管理内容 |
| PROP-A15 | 供应商资质证书 | 清洁服务资格等级和维修企业技术等级证书作为供应商加分 |
| PROP-A16 | 同类业绩证明材料 | 同类项目业绩证明材料较重且续签认定设置不利判断 |
| PROP-A17 | 荣誉奖项 | 安保、消防、环境卫生荣誉作为供应商加分依据 |
| PROP-A18 | 软件著作权和系统类评分 | 物业相关软件著作权或租赁购买软件作为供应商自主知识产权评分 |
| PROP-A19 | 用户需求书人员年龄形象身份限制 | 人员配置表设置年龄上限、退伍军人优先和形象良好等限制 |
| PROP-A20 | 校外服务范围和公共责任边界 | 校门外5米和进出学校10米道路交通协管纳入物业服务范围 |
| PROP-A21 | 应急响应时限 | 应急处置要求10分钟内到达现场，未区分事件类型和响应层级 |
| PROP-A22 | 合同模板错配 | 合同模板出现成桥荷载试验、检测评估报告和试验仪器等非物业内容 |
| PROP-A23 | 合同付款验收违约空白 | 合同验收、付款和违约条款存在关键空白且与按月付款冲突 |

`PROP-A05` 在该项目中已审查但未单独列风险，原因是符合性和星号条款未形成足够独立的确定风险。

## 5. 容易漏报的位置

外部执行主体容易漏报的不是“显眼风险”，而是以下细颗粒动作：

- 响应度评分与基础响应义务重复；
- 承诺函评分替代合同条款；
- 人员社保时点；
- 证明材料和原件备查；
- 体系认证范围特定化；
- 供应商资质证书与体系认证的区别；
- 业绩续签、不利判断和证明材料；
- 校外服务范围和公共责任边界；
- 应急响应时限未分级；
- 合同模板错配与付款验收违约空白的拆分。

这些漏项通常不是知识没有，而是执行主体没有把知识变成强制动作。

## 6. 质量门复核

Codex 在输出前会反问：

- 人员评分读了吗？如果读了，证书、社保、证明材料是否都查了？
- 供应商能力评分读了吗？如果读了，认证、资质、业绩、荣誉、软著是否都查了？
- 用户需求书读了吗？如果读了，年龄形象身份、校外边界、响应时限是否都查了？
- 合同读了吗？如果读了，模板错配、付款、验收、违约是否都查了？
- 风险数量明显偏少时，是否只是把多个风险合并了？
- 原文内容是否真的来自招标文件，而不是解释？

这一步是从 8 条提升到 20 条的关键。

## 7. 输出复现要求

外部执行主体输出审查记录时，应做到：

- 每个风险都有原文位置；
- 原文内容不写解释；
- 问题说明解释风险成立；
- 风险标题具体到对象和异常条件；
- 关联动作ID；
- 关联风险审查点；
- 标记风险等级；
- 提供可执行修改建议；
- 运行记录保留动作执行表和质量门结果。

## 8. 复现成功标准

复现不是要求每次风险数量完全等于 20，而是要求过程完整。

成功标准：

- 文件画像完整；
- 知识路由可解释；
- 动作清单完整；
- 每个动作有状态；
- 逐章读取有记录；
- 风险原子化合理；
- 质量门有结果；
- 漏报、误报能进入复盘；
- 结论能反链知识。

如果外部执行主体只输出少量风险，但没有动作状态和质量门说明，应视为未完成知识驱动审查。
