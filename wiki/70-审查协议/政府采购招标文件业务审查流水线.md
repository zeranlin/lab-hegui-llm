# 政府采购招标文件业务审查流水线

类型:: 审查协议
状态:: 有效
主题:: 业务审查主流程; 审查流水线; 政府采购招标文件
适用范围:: 政府采购货物和服务招标文件合规审查
所属闭环:: 业务审查主流程线
关联总纲:: [[wiki/00-入口/四线闭环知识系统设计]]; [[wiki/00-入口/动作型知识系统建设纲领]]
关联执行规范:: [[wiki/70-审查协议/知识驱动审查执行规范]]
关联复现规范:: [[wiki/70-审查协议/Codex审查过程复现规范]]
关联矩阵:: [[wiki/20-知识点/政府采购逐章审查矩阵]]

## 1. 定位

本流水线是四线闭环中的第二条线：业务审查主流程线。

它回答“收到一份新的政府采购招标文件后，如何利用本 LLM Wiki 的知识完成审查”。这里描述的是 Codex 实际执行审查时采用的方法、流程、判断规则和产物要求。外部执行主体可以读取本流水线，按同样逻辑模拟 Codex 的审查过程。

本流水线不绑定任何具体执行器、命令或系统实现。它只定义业务审查动作。

## 2. 总体流程

```text
新文件进入
  -> 原文抽取
  -> 文件画像
  -> 知识路由
  -> 章节拆解
  -> 动作任务生成
  -> 逐章逐动作审查
  -> 风险原子化
  -> 证据链补齐
  -> 质量门反查
  -> 审查记录生成
  -> 运行记录生成
  -> 人工复核入口
  -> 复盘和知识更新入口
```

每一步都必须有输入、调用知识、执行动作和产物。

## 3. 输入边界

### 3.1 允许使用

- `raw/` 中的原始招标文件；
- `raw/抽取文本/` 中已抽取的文本；
- `wiki/` 中已有的法规、行业基础、知识点、风险审查点、风险库、审查协议、模板和语料；
- `tools/`、`ingest`、`query`、`lint` 等本地维护工具；
- 用户明确允许使用的材料。

### 3.2 禁止使用

标准 AI 审查不得使用：

- 外部标准答案；
- V2 检查结果；
- 人工批注文件；
- 未入库的历史标注；
- 其他目录中的同项目检查结果；
- 审查前从外部样本反推风险。

外部材料只能用于审后精确率提升，不得混入业务审查主流程。

## 4. 阶段一：原文抽取

### 输入

- 原始招标文件；
- 已存在的抽取文本或来源笔记。

### 调用知识

- [[wiki/60-提示词/条款抽取提示词]]
- [[wiki/15-行业基础/招标文件结构]]

### 执行动作

- 将 Word、PDF 或其他格式转为可检索文本；
- 保留章节标题、表格结构、页码或行号；
- 标记公告、需求、评分、合同、格式等主要章节；
- 对金额、日期、编号、资格条件、评分项和合同空白保持原样。

### 产物

- 抽取文本；
- 来源笔记；
- 原文定位能力。

### 容易出错

- 表格列错位；
- 金额合计错误；
- 行号缺失；
- 合同附件未抽取；
- 空白项被忽略。

## 5. 阶段二：文件画像

### 输入

- 原文抽取文本；
- 招标公告和项目基本信息；
- 采购计划、服务需求明细和政策条款。

### 调用知识

- [[wiki/20-知识点/政府采购招标文件画像]]
- [[wiki/20-知识点/采购品目和标的属性审查]]
- [[wiki/15-行业基础/政府采购专项场景画像]]

### 执行动作

抽取并判断：

- 项目编号、项目名称、采购人、代理机构；
- 采购方式、评审方法、是否评定分离；
- 采购品目、采购标的、数量、单位、所属行业；
- 预算金额、最高限价、分项预算和采购计划编号；
- 是否专门面向中小企业、是否接受联合体、是否允许分包、是否允许进口产品；
- 场景标签，例如学校物业、医院物业、法院机关物业、信息化设备；
- 文件章节完整性；
- 初步风险入口。

### 产物

- 文件画像表；
- 知识路由标签；
- 初步审查重点。

### 质量要求

画像不能只是摘要，必须能解释后续为什么调用某些知识和动作协议。

## 6. 阶段三：知识路由

### 输入

- 文件画像；
- 项目地域、采购方式、品类、场景和章节信息。

### 调用知识

- [[wiki/20-知识点/知识分层与路由规则]]
- [[wiki/10-法规依据/法规采集清单]]
- [[wiki/25-风险审查点/风险审查点总览]]
- 命中的品类动作包和审查协议。

### 执行动作

按顺序调用：

```text
国家通用规则
  -> 地方规则
  -> 采购方式规则
  -> 标的属性规则
  -> 品类规则
  -> 场景规则
  -> 章节规则
  -> 试运行规则
```

物业管理项目至少调用：

- [[wiki/15-行业基础/物业管理服务采购背景]]
- [[wiki/20-知识点/物业管理动作化审查包]]
- [[wiki/70-审查协议/物业管理审查动作协议]]
- 人员、认证、资质、业绩、荣誉、软著、合同、响应时限等风险审查点。

### 产物

- 调用知识清单；
- 本次审查适用规则说明；
- 不适用知识说明。

## 7. 阶段四：章节拆解

### 输入

- 原文抽取文本；
- 文件目录；
- 逐章审查矩阵。

### 调用知识

- [[wiki/20-知识点/政府采购逐章审查矩阵]]
- [[wiki/20-知识点/审查作业清单]]

### 执行动作

将文件拆为：

- 招标公告；
- 投标人须知；
- 资格条件；
- 资格性和符合性审查；
- 采购需求或用户需求书；
- 评分办法；
- 政府采购政策；
- 投标文件格式；
- 合同条款；
- 付款、验收和考核附件。

每章形成“已读、已抽取、已判断”的状态。

### 产物

- 逐章审查记录；
- 关键条款摘录；
- 缺失项列表。

## 8. 阶段五：动作任务生成

### 输入

- 文件画像；
- 章节拆解结果；
- 品类动作协议；
- 逐章审查矩阵。

### 调用知识

- [[wiki/70-审查协议/政府采购招标文件审查协议]]
- [[wiki/70-审查协议/物业管理审查动作协议]]
- [[wiki/70-审查协议/知识驱动审查执行规范]]

### 执行动作

生成本次动作清单。每个动作至少包括：

| 字段 | 内容 |
| --- | --- |
| 动作ID | 例如 `PROP-A09` |
| 动作名称 | 与动作协议一致 |
| 必读章节 | 本动作需要读取的原文范围 |
| 触发信号 | 原文中需要查找的信号 |
| 必须检查 | 成立条件、排除条件、缺失判断 |
| 执行状态 | 命中、未命中、待确认 |
| 关联审查点 | 稳定风险审查点 |
| 输出要求 | 风险标题、原文、问题说明和建议口径 |

### 产物

- 动作清单；
- 未命中也需记录的动作列表；
- 待确认动作列表。

### 质量要求

不能只把动作协议当参考材料。动作协议必须变成实际检查任务。

## 9. 阶段六：逐章逐动作审查

### 输入

- 原文；
- 动作清单；
- 风险审查点。

### 执行动作

按章节推进，同时按动作交叉检查：

| 审查域 | 必查动作 |
| --- | --- |
| 预算和标的 | 金额、分项预算、标的名称、数量、所属行业 |
| 政策 | 中小企业、价格扣除、声明函、进口产品 |
| 资格 | 法定资格、特定资格、分公司、关联主体、联合体、分包 |
| 用户需求 | 服务范围、人员配置、响应时限、费用边界、验收 |
| 评分办法 | 响应度、承诺函、人员、认证、资质、业绩、荣誉、软著 |
| 证明材料 | 社保、查询截图、原件备查、合同关键页、证书查询 |
| 合同 | 模板错配、付款、验收、违约、服务期、保密、交接 |

每个动作都要得出：

```text
命中 / 未命中 / 待确认
```

### 产物

- 命中风险候选；
- 未命中说明；
- 待确认事项；
- 已审查未列风险说明。

## 10. 阶段七：风险原子化

### 输入

- 命中风险候选；
- 同一原文中的多重问题；
- 风险原子化规则。

### 调用知识

- [[wiki/70-审查协议/风险原子化规则]]

### 执行动作

对风险进行拆分：

- 证书组合和社保时点分开；
- 证书组合和证明材料分开；
- 需求端人员限制和评分端人员证书分开；
- 体系认证和供应商资质分开；
- 业绩范围和证明材料分开；
- 合同模板错配和付款验收违约空白分开；
- 承诺函评分和合同条款不清分开。

### 产物

- 原子风险清单；
- 合并风险说明；
- 待人工复核风险。

## 11. 阶段八：证据链补齐

### 输入

- 原子风险清单；
- 原文定位；
- 风险审查点；
- 法规依据。

### 执行动作

每条风险补齐：

```text
风险标题
结论类型
风险等级
原文位置
原文内容
问题说明
关联动作ID
关联审查点
审查依据
修改建议
是否需要人工复核
```

### 字段边界

- `原文内容` 只放招标文件原文；
- `问题说明` 写判断理由；
- `关联动作ID` 连接审查动作；
- `关联审查点` 连接稳定规则；
- `审查依据` 引用法规、知识点或风险审查点；
- `修改建议` 给出可执行修改方向。

## 12. 阶段九：质量门反查

### 输入

- 审查记录草稿；
- 动作清单；
- 原子风险清单；
- 逐章审查记录。

### 调用知识

- [[wiki/70-审查协议/质量门规则]]

### 必查问题

- 文件画像是否完整；
- 知识路由是否完整；
- 动作清单是否全部有状态；
- 风险是否有原文；
- 原文内容是否混入解释；
- 人员评分是否反查证书、社保、证明材料；
- 供应商能力是否反查认证、资质、业绩、荣誉、软著；
- 用户需求是否反查人员限制、校外边界、响应时限；
- 合同是否反查模板错配、付款、验收、违约；
- 风险数量异常偏低时是否触发漏项反查。

### 产物

- 质量门结果；
- 退回重审动作；
- 已通过说明。

## 13. 阶段十：审查记录生成

### 输入

- 通过质量门的风险清单；
- 文件画像；
- 逐章审查记录；
- 待确认事项。

### 调用知识

- [[wiki/90-模板/审查记录模板]]

### 产物

- 项目 AI 审查版审查记录。

### 要求

- 只生成一份 AI 审查版；
- 不生成校准版；
- 不混入外部标准答案；
- 风险点服务人工审查人员阅读；
- 关键原文直接可见；
- 风险标题具体、可定位。

## 14. 阶段十一：运行记录生成

### 输入

- 审查过程；
- 使用的知识；
- 动作清单；
- 质量门结果；
- 工具调用。

### 调用知识

- [[wiki/90-模板/AI调度运行记录模板]]

### 产物

- AI 调度运行记录。

### 要求

运行记录必须说明：

- 审查日期和时间；
- 输入文件；
- 使用知识清单；
- 原文读取范围；
- 动作执行情况；
- 风险数量；
- 质量门结果；
- 是否使用外部标注；
- 是否修改知识库；
- 未能精确记录的模型调用次数。

## 15. 阶段十二：人工复核入口

### 输入

- 审查记录；
- 待确认事项；
- 质量门结果。

### 调用知识

- [[wiki/90-模板/人工调整复盘模板]]
- [[wiki/20-知识点/审查精确率提升流程]]

### 执行动作

人工可以：

- 确认风险；
- 驳回风险；
- 调整风险等级；
- 修改标题；
- 补充原文；
- 拆分或合并风险；
- 新增漏报风险；
- 标记需复核地方口径；
- 判断是否形成知识更新申请。

人工调整不能直接污染稳定知识库。

## 16. 阶段十三：复盘和知识更新入口

### 输入

- 人工调整；
- 漏报；
- 误报；
- 新场景；
- 新边界样本。

### 调用知识

- [[wiki/20-知识点/审查精确率提升流程]]
- [[wiki/90-模板/知识更新申请模板]]

### 执行动作

判断调整是否可复用：

```text
不可复用 -> 项目个案备注
可复用 -> 人工调整复盘
  -> 知识更新申请
  -> 复核通过
  -> 回写知识点、风险审查点、风险库、动作协议或质量门
```

## 17. 外部执行主体复现要求

外部执行主体读取本流水线时，应做到：

- 不把本流水线当普通说明文；
- 将每个阶段转成实际执行步骤；
- 记录每个阶段的输入和产物；
- 将品类动作协议转成动作清单；
- 将质量门转成输出前检查；
- 将运行记录作为必交产物；
- 对未命中动作写明原因；
- 对低风险数量触发反查；
- 不把项目样板风险硬编码为固定答案。

## 18. 成功标准

业务审查主流程线成功，不以风险数量单一判断，而以过程完整性判断：

| 标准 | 要求 |
| --- | --- |
| 画像完整 | 项目属性和政策适用可解释 |
| 路由完整 | 调用了正确层级知识 |
| 章节完整 | 公告、需求、评分、合同均已读 |
| 动作完整 | 命中品类动作均有状态 |
| 风险清楚 | 每条风险有原文、说明、依据、建议 |
| 原子化合理 | 不把应拆风险合成一条 |
| 质量门执行 | 有漏项反查记录 |
| 可复核 | 人工能直接看原文和修改建议 |
| 可回写 | 漏报误报能进入复盘和知识更新 |

如果外部执行主体只输出风险清单，而没有画像、动作、质量门和运行记录，就没有完整复现本业务审查流水线。
