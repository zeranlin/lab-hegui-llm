## 1. 目标

本 SOP 用于规范如何从官方公开渠道获取政府采购招标文件或采购文件，作为品目知识包的验证样本。

目标不是批量收集公告，也不是建立招标文件仓库，而是为“骨架已完成，待案例验证”的品目获取少量、完整、可追溯、可用于审查动作验证的样本。

采集后的样本用于：

- 验证现有动作包是否能驱动审查；
- 验证风险审查点是否覆盖高频问题；
- 发现漏报、误报、缺失类风险和原子化问题；
- 形成审查记录、运行记录和知识回写。

## 3. 采集对象

优先采集以下材料：

- 招标文件；
- 采购文件；
- 竞争性磋商文件；
- 询价通知书；
- 用户需求书；
- 评分办法；
- 合同模板；
- 更正公告及更正后的采购文件；
- 澄清答疑文件。

只有公告正文、没有采购文件附件的项目，不进入验证样本库。

### 3.1 文件类型和初始状态

登记样本时，应先看“文件类型”，再确定初始状态：

| 文件类型      | 初始状态 | 处理规则                                     |
| --------- | ---- | ---------------------------------------- |
| 采购公告      | 线索   | 只能作为发现入口；必须继续核验采购文件附件，不能直接作为候选样本         |
| 招标公告      | 线索   | 只能作为发现入口；必须继续核验招标文件或采购文件附件               |
| 竞争性磋商公告   | 线索   | 只能作为发现入口；必须继续核验磋商文件附件                    |
| 询价公告      | 线索   | 只能作为发现入口；必须继续核验询价通知书附件                   |
| 更正公告      | 线索   | 用于判断是否存在新版采购文件；应追踪更正后的文件                 |
| 成交公告      | 淘汰   | 原则上不作为标准验证样本入口；如需使用该项目，应重新查找采购公告或采购文件发布页 |
| 中标公告      | 淘汰   | 原则上不作为标准验证样本入口；如需使用该项目，应重新查找采购公告或采购文件发布页 |
| 结果公告      | 淘汰   | 原则上不作为标准验证样本入口；如需使用该项目，应重新查找采购公告或采购文件发布页 |
| 采购文件      | 候选   | 可以进入完整性核验；通过后才能入选                        |
| 招标文件      | 候选   | 可以进入完整性核验；通过后才能入选                        |
| 竞争性磋商文件   | 候选   | 可以进入完整性核验；通过后才能入选                        |
| 询价通知书     | 候选   | 可以进入完整性核验；通过后才能入选                        |
| 采购文件附件压缩包 | 候选   | 需核验压缩包内容是否完整且来源可追溯                       |

登记时不得因为公告页面出现“附件”“采购文件下载”字样，就直接标为候选。只有已经确认文件类型为采购文件、招标文件、磋商文件、询价通知书或其附件压缩包时，才可标为候选。

## 5. 样本入选标准

一个项目进入验证样本库前，必须满足：

- 来源为官方公开页面；
- 能下载或查看完整采购文件；
- 文件包含采购需求、评分办法和合同或主要履约条款；
- 品目或服务内容明确；
- 文件未被人工批注、标准答案或外部审查结果污染；
- 能保留来源网址、项目名称、采购人、公告日期、下载日期；
- 能保存到 `raw/招标文件/待验证样本/品目/` 或正式品目目录；
- 能生成或更新 [[wiki/40-审查工作台/官方公开样本采集清单]]。

以下材料不得作为标准验证样本：

- 只有中标公告或结果公告，没有采购文件；
- 只有采购公告、招标公告、磋商公告或询价公告，但尚未核验采购文件附件；
- 只有公告截图，没有官方页面；
- 来源无法追溯到官方平台；
- 采购文件需要登录、授权或违反平台规则才能获取；
- 明显是第三方整理、改写或压缩后的非原始文件；
- 已带人工批注、风险标注或标准答案。

## 6. 采集步骤

### 6.1 确定验证目标

先从 [[wiki/00-入口/必备品目知识资产盘点]] 选择一个成熟度为“骨架已完成，待案例验证”的品目。

必须记录：

- 目标品目；
- 需要验证的动作包；
- 需要重点验证的风险审查点；
- 计划采集数量，初始建议 1 至 2 份。

### 6.2 官方来源检索

按“国家平台、省级地方分网、省级一体化平台、市级平台、采购人官网、公共资源交易中心官网”的顺序检索。

检索时优先组合：

```text
品目关键词 + 公开招标 + 招标文件
品目关键词 + 采购文件 + 政府采购
品目关键词 + 竞争性磋商 + 采购文件
品目关键词 + 用户需求书 + 评分办法
```

不得只按“风险关键词”检索样本，避免样本选择被已知风险引导。

### 6.3 页面核验

下载前必须核验：

- 页面域名是否为政府、财政、公共资源交易中心或采购人官方域名；
- 公告类型是否为采购公告、招标公告、竞争性磋商公告或更正公告；
- 是否有采购文件下载入口；
- 是否有采购人、代理机构、项目编号、预算金额和开标时间；
- 是否存在更正公告，若有，应优先采集更正后的文件。

### 6.4 文件保存

文件保存规则：

```text
raw/招标文件/待验证样本/品目/项目编号-项目简称-来源日期.扩展名
```

如果样本已经决定进入正式品目验证，可保存为：

```text
raw/招标文件/品目/项目编号-项目简称.扩展名
```

禁止修改采购文件内容。若需要转换文本，应另存到 `raw/抽取文本/`。

### 6.5 登记采集清单

每采集一个候选样本，必须更新 [[wiki/40-审查工作台/官方公开样本采集清单]]。

至少登记：

- 品目；
- 项目名称；
- 采购人；
- 来源平台；
- 来源网址；
- 公告日期；
- 下载时间；
- 文件类型；
- 是否含采购需求、评分办法、合同；
- 入选判断；
- 后续动作。

### 6.6 入库和验证

样本入选后，按 [[wiki/80-SOP/新增政府采购审查品目知识包SOP]] 执行：

1. `./ingest` 建立来源笔记；
2. 抽取项目画像；
3. 路由对应品目动作包和审查协议；
4. 逐动作执行；
5. 风险原子化；
6. 质量门反查；
7. 生成审查记录和运行记录；
8. 复盘漏报、误报和知识缺口；
9. 回写知识。

## 7. 质量门

采集工作完成前，必须检查：

- 是否每个样本都有官方来源网址；
- 是否每个样本都有完整采购文件；
- 是否避免了只有公告没有文件的项目；
- 是否检查了更正公告；
- 是否记录下载时间和保存路径；
- 是否说明该样本要验证哪些动作；
- 是否没有把外部批注、标准答案、人工检查结果混入 AI 审查阶段；
- 是否没有大规模无目标下载。

未通过质量门的样本，只能保留为“线索”，不得进入验证样本。

## 8. 完成判定

一个品目的公开样本采集完成，至少应满足：

- 已登记 1 至 2 个候选样本；
- 至少 1 个样本通过入选标准；
- 已保存原始采购文件；
- 已登记来源和保存路径；
- 已明确要验证的动作包、风险审查点和质量门；
- 已准备进入 AI 审查验证。

一个品目的样本验证完成，还必须形成：

- 来源笔记；
- 审查记录；
- 运行记录；
- 漏报误报复盘或知识更新申请；
- `wiki/log.md` 记录。

## 9. 禁止事项

- 不从非官方转载页面直接下载并入库；
- 不把搜索引擎摘要当作来源；
- 不采集需要绕过登录、验证码、权限或平台规则的文件；
- 不把人工批注或标准答案当作 AI 审查输入；
- 不为了凑数量下载大量同质文件；
- 不在没有完整采购文件时生成风险审查样本；
- 不修改 `raw/` 中的原始文件。
