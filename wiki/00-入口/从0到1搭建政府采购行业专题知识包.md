## 1. 这份文档解决什么问题

这份文档面向第一次接触本知识库的人，回答一个最基础的问题：

```text
如果我要从零开始搭建一个政府采购行业合规审查专题知识包，应当怎么做？
```

这里的“专题知识包”不是资料夹，也不是法规汇编，而是一个可被人理解、可被 AI 调度、可被项目验证、可持续更新的政府采购合规审查能力模块。

它要把一个专题中的业务理解、法规政策、监管要求、风险判断、证据链、审查动作、输出模板和复盘经验组织起来，使后续审查人员或外部执行主体能够按统一口径完成审查。

## 2. 专题知识包是什么

政府采购行业专题知识包，是围绕某一个合规审查目标组织起来的知识模块。

它至少要回答：

- 这个专题审什么；
- 为什么要审；
- 适用于哪些采购活动、采购方式、品目和场景；
- 需要看哪些文件、数据和证据；
- 有哪些典型风险；
- 风险成立和不成立的边界是什么；
- 审查动作如何执行；
- 审查结果如何输出；
- 人工调整后如何回写知识。

一个完整专题知识包的逻辑结构是：

```text
业务背景
  -> 法规政策
  -> 审查对象
  -> 问题类型
  -> 证据链
  -> 审查动作
  -> 风险审查点
  -> 语料样本
  -> 输出模板
  -> 质量门
  -> 复盘回写机制
```

## 3. 专题知识包不是什么

专题知识包容易被误建成三种东西：

| 容易误建成 | 问题 | 正确做法 |
| --- | --- | --- |
| 法规摘抄库 | 只知道法规文字，不知道怎么审 | 把法规拆成审查对象、触发信号和判断规则 |
| 项目材料库 | 堆了很多项目记录，但不能复用 | 从项目中提炼稳定风险审查点和语料样本 |
| 提示词集合 | 只靠提示词要求模型“认真审查” | 用知识、动作协议和质量门约束审查过程 |

本系统中的专题知识包必须能驱动审查动作，而不是只保存信息。

## 4. 政府采购行业专题知识包分类

政府采购行业可以按不同视角形成专题知识包。

### 4.1 招标文件合规性专题知识包

这是当前本知识库的主线专题。

它关注招标文件本身是否合规、完整、公平、可执行。

典型子专题包括：

- 招标公告审查；
- 资格条件审查；
- 采购需求审查；
- 评分办法审查；
- 政府采购政策审查；
- 合同条款审查；
- 投标文件格式审查；
- 缺失类风险审查。

当前落点包括：

- [[wiki/20-知识点/政府采购招标文件画像]]
- [[wiki/20-知识点/政府采购逐章审查矩阵]]
- [[wiki/70-审查协议/政府采购招标文件业务审查流水线]]
- [[wiki/70-审查协议/政府采购招标文件审查协议]]

### 4.2 四类专项整治专题知识包

这是监管专题，不完全等同于招标文件审查专题。

根据财政部、公安部、市场监管总局关于政府采购领域“四类”违法违规行为专项整治的通知，监管重点包括：

- 采购人设置差别歧视条款；
- 代理机构乱收费；
- 供应商提供虚假材料；
- 供应商围标串标。

官方来源示例：

- [财政部 公安部 市场监管总局关于开展2025年政府采购领域“四类”违法违规行为专项整治工作的通知](https://gks.mof.gov.cn/ztztz/zhengfucaigouguanli/202506/t20250623_3966295.htm)

需要注意：

- 采购人设置差别歧视条款，通常可以从采购文件中识别；
- 代理机构乱收费，需要代理协议、收费凭证、保证金退还记录等材料；
- 供应商提供虚假材料，需要投标文件、证书、检测报告、声明函和外部核验；
- 供应商围标串标，通常需要投标文件、报价、保证金、文件元数据、联系人、IP 或其他交易数据。

因此，四类专项整治专题知识包必须先区分：

```text
能从招标文件直接审查的问题
  与
必须依赖投标文件、交易数据或外部核验的问题
```

### 4.3 政府采购政策功能专题知识包

这类专题关注政府采购政策功能是否正确落实。

典型专题包括：

- 中小企业政策；
- 节能产品政策；
- 环境标志产品政策；
- 绿色采购政策；
- 进口产品政策；
- 监狱企业政策；
- 残疾人福利性单位政策。

这类知识包要重点处理：

- 是否适用政策；
- 文件是否写明政策口径；
- 价格扣除、预留份额、声明函是否正确；
- 采购标的所属行业是否一致；
- 是否存在政策适用错误或遗漏。

### 4.4 采购需求管理专题知识包

这类专题关注采购需求是否完整、明确、合规、可执行。

典型专题包括：

- 需求完整性；
- 技术参数指向性；
- 服务范围和边界；
- 商务条件；
- 履约验收；
- 付款条件；
- 风险责任分配。

它通常需要和 [[wiki/20-知识点/采购需求与评审因素闭环]] 联动。

### 4.5 评分办法和评审因素专题知识包

这类专题关注评分因素是否合法、合理、客观、与采购需求相关。

典型专题包括：

- 人员证书评分；
- 企业资质认证评分；
- 同类业绩评分；
- 荣誉奖项评分；
- 方案类主观评分；
- 价格评分；
- 响应度评分；
- 评审因素与采购需求脱节。

### 4.6 合同履约和验收专题知识包

这类专题关注合同能否落地执行。

典型专题包括：

- 合同模板错配；
- 付款方式不清；
- 验收标准缺失；
- 违约责任不明确；
- 服务交接责任不清；
- 采购需求、评分办法和合同条款不一致。

### 4.7 采购品目和场景专项知识包

这类专题按采购品目或场景搭建。

典型专题包括：

- 物业管理；
- 信息化设备；
- 医疗设备；
- 学校服务；
- 医院后勤；
- 法院机关物业；
- 食堂餐饮；
- 安保服务；
- 运维服务。

品目专题的价值是把通用规则落到具体行业语境中，形成场景画像、专项动作和典型语料。

当前物业管理样板落点：

- [[wiki/15-行业基础/物业管理服务采购背景]]
- [[wiki/20-知识点/物业管理动作化审查包]]
- [[wiki/70-审查协议/物业管理审查动作协议]]
- [[wiki/40-审查工作台/物业管理四线闭环实施说明]]

### 4.8 地域和平台规则专题知识包

政府采购规则存在地域和平台差异。

这类专题关注：

- 国家规则；
- 省级规则；
- 市级规则；
- 区县规则；
- 集中采购目录；
- 限额标准；
- 交易平台模板；
- 信用评价规则；
- 本地条例和实施细则。

这类知识包必须和 [[wiki/20-知识点/知识分层与路由规则]] 联动，避免把某地规则误用于全国项目。

## 5. 从 0 到 1 的十步构建法

### 第 1 步：定义专题边界

先说清楚这个专题解决什么问题。

建议使用字段：

```text
专题名称::
审查目标::
适用阶段::
适用对象::
适用采购方式::
适用品目或场景::
适用地域::
不适用范围::
```

边界定义必须写“不适用范围”。没有不适用范围，知识包很容易无限扩张。

示例：

```text
专题名称:: 四类专项整治专题知识包
审查目标:: 识别四类重点违法违规行为及其线索
适用阶段:: 采购文件审查; 项目执行检查; 投标文件核查; 专项整治抽查
不适用范围:: 不能仅凭招标文件直接认定供应商虚假材料或围标串标
```

### 第 2 步：建立业务对象模型

把专题涉及的人、文件、行为和数据讲清楚。

建议按四类对象建模：

| 对象 | 示例 |
| --- | --- |
| 主体 | 采购人、代理机构、供应商、评审专家、监管部门 |
| 文件 | 招标文件、投标文件、采购需求、合同、代理协议、质疑投诉材料 |
| 数据 | 报价、保证金、IP、文件元数据、证书编号、业绩材料、信用信息 |
| 行为 | 设置条件、收费、响应、评审、履约、投诉、核验、移送 |

业务对象模型的作用是告诉新人：这个专题不是抽象风险，而是发生在具体主体、文件、数据和行为中的问题。

### 第 3 步：梳理法规政策依据

法规政策不能只入库为原文，应拆成审查动作映射。

建议结构：

```text
法规或政策来源
  -> 约束对象
  -> 约束行为
  -> 对应文件或数据
  -> 可触发问题类型
  -> 可支撑风险审查点
  -> 输出口径
```

示例：

```text
不得以不合理条件对供应商实行差别待遇或歧视待遇
  -> 约束采购人和采购代理机构
  -> 对应资格条件、采购需求、评分办法、合同条款
  -> 触发本地化限制、特定供应商指向、特定证书、特定业绩等问题
```

### 第 4 步：拆出问题类型

把专题拆成可以审查的小问题。

拆分原则：

- 一个问题类型应对应一组相似证据；
- 一个问题类型应能转成审查动作；
- 一个问题类型应能形成稳定风险审查点；
- 不同证据链的问题不要强行合并。

示例：

```text
招标文件合规性专题
  -> 资格条件过度
  -> 采购需求不明确
  -> 技术参数指向性
  -> 评分因素不当
  -> 业绩奖项限制
  -> 中小企业政策错误
  -> 合同条款不清
  -> 实质性条款扩大化
```

### 第 5 步：建立证据链

每类问题必须说明看什么证据。

建议结构：

```text
问题类型::
主要证据::
辅助证据::
原文信号::
缺失信号::
能否仅凭招标文件判断::
需要人工复核情形::
```

示例：

| 问题类型 | 主要证据 | 能否仅凭招标文件判断 |
| --- | --- | --- |
| 本地化限制 | 招标公告、资格条件、采购需求、评分办法 | 通常可以 |
| 代理机构乱收费 | 收费条款、代理协议、收费凭证、保证金退还记录 | 通常不够 |
| 虚假材料 | 投标文件、证书、检测报告、声明函、核验结果 | 通常不够 |
| 围标串标 | 投标文件、报价、保证金、元数据、交易数据 | 通常不够 |

证据链是避免误报的关键。

### 第 6 步：转成审查动作

审查动作是专题知识包能否被 AI 执行的核心。

每个动作建议使用：

```text
动作ID::
动作名称::
看哪里::
找什么::
触发信号::
缺失信号::
判断规则::
排除条件::
输出字段::
关联风险审查点::
需要人工复核情形::
```

动作写法示例：

```text
动作ID:: TOPIC-A01
动作名称:: 本地化限制检查
看哪里:: 资格条件; 采购需求; 评分办法; 合同履约要求
找什么:: 注册地、本地分支机构、本地服务网点、本地业绩、近场响应、驻场要求
判断规则:: 与采购需求无直接关系，或将本地条件作为准入、加分、中标条件时，形成限制排斥风险
排除条件:: 仅为履约服务响应安排，且不以本地注册、本地机构或本地业绩作为准入或加分条件
```

### 第 7 步：沉淀风险审查点

风险审查点是最小稳定规则单元。

每个风险审查点至少包括：

```text
风险名称::
适用范围::
审查章节::
识别信号::
判断规则::
排除条件::
常见误报::
典型原文::
法规依据::
风险等级口径::
修改建议::
```

项目里的具体风险点必须能反链到风险审查点。不能反链的，先作为待归类风险进入复盘。

### 第 8 步：补充语料样本

没有语料样本，AI 很难稳定识别。

语料至少分三类：

| 类型 | 作用 |
| --- | --- |
| 正例 | 确实构成风险的原文 |
| 反例 | 看起来像风险但不构成的原文 |
| 边界样本 | 需要结合项目背景或人工判断的原文 |

语料样本必须保留来源、章节、页码或行号，并说明它支持哪个审查动作或风险审查点。

### 第 9 步：设计输出模板和质量门

专题知识包必须规定怎么输出。

风险点字段至少包括：

```text
风险标题
结论类型
风险等级
原文位置
原文内容
问题说明
关联审查点
审查依据
修改建议
是否需人工复核
```

质量门至少检查：

- 是否完成文件画像；
- 是否读取专题知识包；
- 是否执行全部必查动作；
- 是否有原文证据或明确缺失事实；
- 是否误把解释写入 `原文内容`；
- 是否存在不能凭当前材料判断却直接下结论的问题；
- 是否输出运行记录；
- 是否把可复用漏报误报进入复盘。

### 第 10 步：通过项目复盘回写知识

专题知识包不是一次建成，而是通过项目审查持续进化。

```text
项目审查
  -> 人工调整
  -> 漏报误报归因
  -> 知识更新申请
  -> 复核
  -> 更新专题知识包
  -> 下一项目验证
```

回写时要区分：

- 法规依据缺失，回写法规层；
- 业务背景不足，回写行业基础层；
- 审查动作缺失，回写知识点或动作协议；
- 风险规则缺失，回写风险审查点；
- 原文信号不足，回写语料样本；
- 输出不便于人工使用，回写模板。

## 6. 专题知识包标准目录

一个专题知识包可以采用以下目录结构：

```text
专题名称/
  01-专题边界.md
  02-业务对象模型.md
  03-法规政策映射.md
  04-问题类型表.md
  05-证据链表.md
  06-审查动作协议.md
  07-风险审查点清单.md
  08-语料样本.md
  09-输出模板.md
  10-质量门.md
  11-复盘回写规则.md
```

在本 LLM Wiki 中，不一定要物理创建一个同名文件夹，但逻辑上必须具备这些内容。

## 7. 最小可用版本

一个专题知识包不需要一开始就完整。

最小可用版本应至少包含：

- 1 个专题边界说明；
- 1 个业务对象模型；
- 1 个法规依据清单；
- 1 个问题类型表；
- 1 个证据链表；
- 1 组审查动作；
- 5 至 10 个风险审查点；
- 若干典型原文样本；
- 1 个输出模板；
- 1 个质量门清单。

达到最小可用版本后，就可以用真实项目验证，而不是继续空转设计。

## 8. 专题知识包如何驱动 AI 审查

专题知识包驱动 AI 审查的方式不是让 AI “学习资料”，而是让 AI 按知识包执行动作。

标准执行链路：

```text
输入项目材料
  -> 建立文件或项目画像
  -> 命中专题知识包
  -> 读取专题边界和证据链
  -> 生成动作清单
  -> 逐项执行动作
  -> 输出命中、未命中、待确认
  -> 形成风险点或线索
  -> 执行质量门
  -> 生成审查记录和运行记录
```

如果 AI 没有输出动作状态和质量门结果，就不能证明它真正使用了专题知识包。

## 9. 专题知识包如何和四线闭环连接

专题知识包主要属于第一条线：知识生成管理线。

但它会贯穿四条线：

| 线 | 专题知识包的作用 |
| --- | --- |
| 知识生成管理线 | 定义专题边界、对象模型、证据链、动作和风险审查点 |
| 业务审查主流程线 | 按专题知识包执行审查并输出项目结果 |
| 审后调整和精确率提升线 | 通过人工调整发现专题知识包缺口 |
| 外部执行主体使用线 | 让外部执行主体读取专题知识包并复现审查动作 |

## 10. 示例：招标文件合规性专题知识包

招标文件合规性专题知识包的目标是识别采购文件中的合规风险。

适合从招标文件直接审查的问题包括：

- 资格条件是否过度；
- 采购需求是否完整明确；
- 技术参数是否指向特定供应商；
- 评分因素是否与采购需求相关；
- 中小企业政策是否正确；
- 合同付款、验收和违约条款是否清楚；
- 是否存在应写未写的缺失类风险。

当前本知识库已经以该专题为主线建设，并在物业管理品目中形成样板。

## 11. 示例：四类专项整治专题知识包

四类专项整治专题知识包的目标是围绕监管重点识别违法违规行为或线索。

建议拆成四个子包：

| 子包 | 主要审查对象 | 是否适合仅凭招标文件判断 |
| --- | --- | --- |
| 采购人设置差别歧视条款 | 招标文件、采购需求、评分办法 | 多数可以 |
| 代理机构乱收费 | 代理协议、收费凭证、保证金记录、采购文件收费条款 | 通常不够 |
| 供应商提供虚假材料 | 投标文件、检测报告、认证证书、业绩、声明函、核验结果 | 通常不够 |
| 供应商围标串标 | 投标文件、报价、保证金、元数据、交易数据 | 通常不够 |

因此，这个专题知识包必须把“文件审查风险”和“后续核查线索”分开输出。

## 12. 示例：物业管理品目专题知识包

物业管理品目专题知识包的目标是把政府采购通用合规规则落到物业服务场景。

它需要回答：

- 物业服务采购文件一般有哪些章节；
- 学校、医院、法院机关、建筑机电物业的场景差异是什么；
- 人员配置、证书、社保、年龄形象、响应时限、合同付款验收有哪些高频风险；
- 哪些风险是物业场景常见，哪些只是通用政府采购风险；
- 外部执行主体如何执行 `PROP-A01` 至 `PROP-A23` 动作。

当前物业管理样板已经具备专题知识包雏形，后续应继续补充正例、反例和边界样本。

## 13. 关键原则

- 先定义专题，再收集资料。
- 先理解业务对象，再拆风险类型。
- 先建证据链，再写判断结论。
- 先动作化，再交给 AI 执行。
- 项目结果不是稳定知识，必须经过复盘才能回写。
- 能从招标文件判断的问题和必须依赖投标文件、交易数据或外部核验的问题要分开。
- 每个专题知识包都要能服务人、AI 和外部执行主体。
