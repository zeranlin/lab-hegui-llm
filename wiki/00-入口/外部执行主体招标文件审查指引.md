## 1. 定位

本指引面向外部执行主体，说明收到一份政府采购招标文件后，如何读取本 LLM Wiki 的知识，并按同一套审查动作生成可审计结果。

这里的外部执行主体可以是：

- AI Agent；
- 自动化执行器；
- 脚本系统；
- 业务平台；
- 人工审查助理。

外部执行主体的任务不是总结文件，也不是自由发挥找风险，而是按本知识库定义的流程完成：

```text
输入招标文件
  -> 文件画像
  -> 知识路由
  -> 动作清单
  -> 逐动作执行
  -> 风险原子化
  -> 质量门反查
  -> 报告生成
  -> 运行记录
```

每一步都必须留下中间产物。没有中间产物，就不能证明执行主体真正使用了本知识系统。

## 3. 标准流水线和中间产物

外部执行主体必须按以下流水线执行，并生成对应中间产物。

| 环节    | 必要中间产物                 | 进入下一步的条件          |
| ----- | ---------------------- | ----------------- |
| 文件画像  | `01-文件画像`              | 关键项目字段已抽取，未见字段已标注 |
| 知识路由  | `02-知识路由表`             | 必读知识和命中知识均有调用原因   |
| 动作清单  | `03-动作清单`              | 必做动作完整，动作均有来源知识   |
| 逐动作执行 | `04-动作执行记录`            | 每个动作均有状态和已读范围     |
| 风险原子化 | `05-原子风险清单`            | 候选风险已拆成可单独整改的问题   |
| 质量门反查 | `06-质量门检查表`            | 无未执行必做动作，无缺少证据的风险 |
| 报告生成  | `07-AI审查记录`; `08-运行记录` | 报告能反链画像、路由、动作和质量门 |

中间产物可以是 Markdown、JSON、表格或执行器内部结构化对象，但必须能在运行记录中追溯。

推荐命名：

```text
项目名称/
  01-文件画像.md
  02-知识路由表.md
  03-动作清单.md
  04-动作执行记录.md
  05-原子风险清单.md
  06-质量门检查表.md
  07-AI审查记录.md
  08-运行记录.md
```

本 LLM Wiki 项目内最终沉淀的正式产物仍以 `wiki/40-审查工作台/审查记录/` 和 `wiki/40-审查工作台/运行记录/` 为准。外部执行主体是否保留单独中间文件，由其实现决定，但运行记录必须列明这些中间产物。

## 4. 环节一：文件画像

### 4.1 目的

文件画像用于判断“这是一份什么文件”，是知识路由的前置条件。

执行主体不得跳过画像直接输出风险。

### 4.2 输入

- 原始招标文件；
- 抽取文本；
- 招标公告、采购需求、评分办法、合同和附件；
- [[wiki/20-知识点/政府采购招标文件画像]]；
- [[wiki/60-提示词/招标文件画像提示词]]。

### 4.3 必须抽取字段

`01-文件画像` 至少包含：

```text
项目编号::
项目名称::
采购人::
代理机构::
采购方式::
评审方法::
预算金额::
最高限价::
采购品目::
采购标的::
标的属性::
标的所属行业::
适用地域::
交易平台::
是否专门面向中小企业::
是否接受联合体::
是否允许分包::
是否允许进口产品::
场景标签::
文件章节清单::
初步风险入口::
画像置信度::
待确认项::
```

### 4.4 通过条件

- 项目编号、项目名称、采购人、采购方式、评审方法、预算金额、采购品目至少有抽取结果；
- 未见字段必须写 `未见`，不确定字段必须写 `待确认`；
- 能说明为什么命中某个品类或场景；
- 能说明文件是否具备招标公告、采购需求、评分办法、合同条款等关键章节。

### 4.5 失败处理

如果无法读取原文或关键字段严重缺失，应停止审查，生成失败说明，不得编造画像。

## 5. 环节二：知识路由

### 5.1 目的

知识路由用于决定本次审查调用哪些知识。

执行主体不得只按关键词检索风险，应根据文件画像路由知识。

### 5.2 路由顺序

固定路由顺序：

```text
全国通用规则
  -> 地方规则
  -> 采购方式规则
  -> 标的属性规则
  -> 品类规则
  -> 场景规则
  -> 章节规则
  -> 风险审查点
  -> 输出模板和质量门
```

### 5.3 中间产物字段

`02-知识路由表` 至少包含：

```text
画像字段
命中规则
调用知识页
调用原因
适用层级
适用地域
适用品类或场景
是否必读
执行状态
```

### 5.4 必须路由的基础知识

无论品类如何，必须路由：

- [[wiki/70-审查协议/知识驱动审查执行规范]]
- [[wiki/70-审查协议/政府采购招标文件业务审查流水线]]
- [[wiki/70-审查协议/政府采购招标文件审查协议]]
- [[wiki/20-知识点/政府采购招标文件画像]]
- [[wiki/20-知识点/知识分层与路由规则]]
- [[wiki/20-知识点/政府采购逐章审查矩阵]]
- [[wiki/25-风险审查点/风险审查点总览]]
- [[wiki/70-审查协议/风险原子化规则]]
- [[wiki/70-审查协议/质量门规则]]
- [[wiki/90-模板/审查记录模板]]
- [[wiki/90-模板/AI调度运行记录模板]]

如果画像命中物业管理，必须额外路由：

- [[wiki/15-行业基础/物业管理服务采购背景]]
- [[wiki/20-知识点/物业管理动作化审查包]]
- [[wiki/70-审查协议/物业管理审查动作协议]]
- [[wiki/40-审查工作台/物业管理四线闭环实施说明]]

### 5.5 通过条件

- 每个调用知识页都有调用原因；
- 地方规则、品类规则、场景规则的适用边界已说明；
- 命中物业管理时，物业动作协议已列入必读；
- 路由表进入运行记录。

### 5.6 失败处理

如果无法判断品类或场景，应先按通用招标文件审查协议执行，并将品类判断列为待确认，不得强行套用某个品类动作协议。

## 6. 环节三：动作清单

### 6.1 目的

动作清单把知识路由结果转成“本次必须执行什么”。

动作清单不是模型自由生成的任务列表，应来自逐章矩阵、通用审查协议和品类动作协议。

### 6.2 中间产物字段

`03-动作清单` 至少包含：

```text
动作ID
动作名称
来源知识
必读章节
触发信号
必须检查
预期输出
关联风险审查点
是否必做
执行状态
未执行原因
```

### 6.3 物业管理必做动作

如果文件画像命中物业管理，必须生成并执行 `PROP-A01` 至 `PROP-A23`：

| 动作ID     | 动作名称            |
| -------- | --------------- |
| PROP-A01 | 采购计划和预算完整性      |
| PROP-A02 | 服务需求明细和所属行业     |
| PROP-A03 | 中小企业政策和声明函口径    |
| PROP-A04 | 资格条件和分公司授权      |
| PROP-A05 | 实质性条款和投标无效边界    |
| PROP-A06 | 响应度评分与基础响应重复    |
| PROP-A07 | 服务期满后过渡服务承诺     |
| PROP-A08 | 违约承诺评分          |
| PROP-A09 | 项目负责人证书组合       |
| PROP-A10 | 项目负责人社保时点       |
| PROP-A11 | 服务团队证书组合        |
| PROP-A12 | 服务团队社保时点        |
| PROP-A13 | 证明材料和原件备查       |
| PROP-A14 | 体系认证范围          |
| PROP-A15 | 供应商资质证书         |
| PROP-A16 | 同类业绩证明材料        |
| PROP-A17 | 荣誉奖项            |
| PROP-A18 | 软件著作权和系统类评分     |
| PROP-A19 | 用户需求书人员年龄形象身份限制 |
| PROP-A20 | 校外服务范围和公共责任边界   |
| PROP-A21 | 应急响应时限          |
| PROP-A22 | 合同模板错配          |
| PROP-A23 | 合同付款验收违约空白      |

动作详情以 [[wiki/70-审查协议/物业管理审查动作协议]] 为准。

### 6.4 通过条件

- 动作清单覆盖画像命中的采购方式、标的属性、品类、场景和章节；
- 必做动作没有缺失；
- 每个动作都有来源知识；
- 每个动作都有执行状态占位；
- 动作清单进入运行记录。

### 6.5 失败处理

如果动作清单无法覆盖关键章节，应回到知识路由补充知识，不得直接进入风险输出。

## 7. 环节四：逐动作执行

### 7.1 目的

逐动作执行用于证明执行主体按动作清单读取原文，而不是只做摘要或关键词命中。

### 7.2 中间产物字段

`04-动作执行记录` 至少包含：

```text
动作ID
动作名称
执行状态：命中 / 未命中 / 待确认 / 不适用
读取章节
读取范围
原文位置
原文摘录
命中信号
初步判断
关联审查点
是否形成候选风险
待确认原因
```

### 7.3 执行要求

- 每个动作都必须有状态；
- 命中动作必须有原文证据；
- 待确认动作必须说明缺少什么材料或依据；
- 未命中动作必须说明已读范围；
- 不适用动作必须说明不适用原因；
- 不能跳过动作直接写风险点。

### 7.4 章节覆盖

至少应覆盖：

| 章节      | 必查重点                       |
| ------- | -------------------------- |
| 招标公告    | 资格条件、采购方式、预算、联合体、中小企业政策    |
| 采购计划和预算 | 采购计划编号、预算金额、最高限价、标的明细、报价口径 |
| 政府采购政策  | 中小企业、进口产品、节能环保、声明函         |
| 资格和符合性  | 资格条件、分公司、关联主体、实质性条款、投标无效   |
| 用户需求书   | 服务范围、人员配置、费用边界、响应时限、验收考核   |
| 评分办法    | 响应度、方案、人员、认证、资质、业绩、荣誉、软著   |
| 证明材料    | 社保、查询截图、原件备查、合同关键页、证书材料    |
| 合同条款    | 服务范围、付款、验收、违约、模板错配、交接责任    |

没有发现风险的章节，也要说明已审查。

### 7.5 通过条件

- 动作清单中的必做动作全部有执行状态；
- 命中和待确认动作有原文位置或明确缺失事实；
- 未命中动作有已读范围；
- 逐动作执行记录进入运行记录。

### 7.6 失败处理

如果存在未执行必做动作，应回到该动作补读原文。质量门不得通过。

## 8. 环节五：风险原子化

### 8.1 目的

风险原子化把候选风险拆成审查人员能逐条理解、逐条修改、逐条复核的独立风险。

不得把多个问题写成一条大风险。

### 8.2 中间产物字段

`05-原子风险清单` 至少包含：

```text
风险ID
来源动作ID
风险标题
结论类型
风险等级
原文位置
原文内容
问题说明
关联审查点
审查依据
修改建议
是否需人工复核
合并或拆分说明
```

### 8.3 必须拆分的情形

以下情况必须拆分：

- 人员证书组合和社保时点；
- 人员证书组合和证明材料；
- 用户需求人员限制和评分人员证书；
- 体系认证和供应商资质；
- 业绩范围和业绩证明材料；
- 合同模板错配和付款验收违约空白；
- 承诺函评分和合同条款不清；
- 供应商认证、资质、荣誉、业绩、软著等不同能力证明。

### 8.4 字段要求

- `原文内容` 只能放招标文件原文，不写解释；
- `问题说明` 写风险成立理由；
- `来源动作ID` 对应动作清单；
- `关联审查点` 对应 `wiki/25-风险审查点/`；
- `修改建议` 必须可执行；
- 依据不确定时，标记 `需进一步确认`。

### 8.5 通过条件

- 每个风险点都能反链来源动作；
- 每个风险点都有原文证据或明确缺失事实；
- 每个风险点至少关联一个风险审查点；
- 不存在无法单独整改的大合并风险。

### 8.6 失败处理

如发现过度合并，应按 [[wiki/70-审查协议/风险原子化规则]] 拆分后再进入质量门。

## 9. 环节六：质量门反查

### 9.1 目的

质量门用于输出前反向检查漏项、误报、证据缺失、动作漏执行和字段不合格。

质量门不是形式检查，而是能决定报告是否允许定稿。

### 9.2 中间产物字段

`06-质量门检查表` 至少包含：

```text
质量门ID
检查项
检查结果：通过 / 未通过 / 待确认
发现问题
回退环节
处理动作
复查结果
```

### 9.3 最低质量门

必须检查：

- 文件画像完整性；
- 知识路由完整性；
- 动作清单完整性；
- 逐动作执行完整性；
- 逐章覆盖完整性；
- 原文证据完整性；
- `原文内容` 字段纯净性；
- 风险原子化完整性；
- 缺失类风险检查；
- 人员评分反查；
- 供应商能力评分反查；
- 用户需求书反查；
- 合同条款反查；
- 方案和承诺评分反查；
- 异常低风险数量反查；
- 待确认项清单。

具体规则以 [[wiki/70-审查协议/质量门规则]] 为准。

### 9.4 异常低风险数量反查

质量门不得把风险数量作为硬性指标，但当同类文件只输出少量风险，且文件包含完整评分办法、用户需求书和合同条款时，必须触发反查：

- 是否只检索风险关键词，没有逐章读取；
- 是否只命中标题明显的风险，漏掉缺失类风险；
- 是否把多条人员评分风险合并成一条；
- 是否漏读合同附件或合同模板；
- 是否未记录未命中动作；
- 是否未执行品类动作协议。

反查结果必须写入运行记录。没有新增风险也要说明反查范围。

### 9.5 通过条件

- 没有未执行的必做动作；
- 没有缺少原文证据的风险点；
- 没有把解释写进 `原文内容`；
- 不确定依据已标记待确认；
- 异常低风险数量已反查；
- 质量门检查表进入运行记录。

### 9.6 失败处理

质量门不通过时，不得输出最终审查记录。处理顺序：

1. 回到缺失动作；
2. 补读原文；
3. 重新判断命中、未命中或待确认；
4. 必要时拆分风险；
5. 更新原子风险清单；
6. 更新运行记录；
7. 再次执行质量门。

## 11. 禁止事项

外部执行主体不得：

- 使用外部 V2、标准答案、人工批注反推风险；
- 只读摘要，不读原文；
- 跳过文件画像；
- 跳过知识路由；
- 不生成动作清单；
- 不记录逐动作执行状态；
- 只按关键词检索风险；
- 把多个应拆分风险合并成一条；
- 把问题说明写进 `原文内容`；
- 生成无原文证据的风险；
- 跳过质量门；
- 质量门不通过仍输出最终报告；
- 自动改写稳定知识库；
- 生成第二套校准版审查记录冒充 AI 审查结果。

## 12. 初始化成功标准

外部执行主体只有满足以下条件，才算成功初始化：

- 能说明本任务输入是一份政府采购招标文件；
- 能读取本指引列出的必读知识；
- 能建立 `01-文件画像`；
- 能生成 `02-知识路由表`；
- 能生成 `03-动作清单`；
- 能生成 `04-动作执行记录`；
- 能生成 `05-原子风险清单`；
- 能生成 `06-质量门检查表`；
- 能生成 `07-AI审查记录`；
- 能生成 `08-运行记录`；
- 能逐章逐动作读取原文；
- 能输出风险点并关联来源动作ID和审查点；
- 能执行风险原子化；
- 能执行质量门；
- 能在运行记录中列明中间产物和质量门结果。

如果只能输出一段总结或少量风险，但没有画像、知识路由、动作清单、动作执行记录、质量门和运行记录，视为未成功初始化。

## 13. 指引维护规则

本指引是 `lab-hegui-llm` 面向外部执行主体的执行入口协议。它不是普通说明文档，而是外部执行主体读取知识库、生成审查动作、输出中间产物和形成报告的接口契约。

当本知识库中的关键知识发生变化时，必须判断是否影响本指引。

### 13.1 必须评估是否更新本指引的变化

以下变化必须评估本指引是否需要同步更新：

- [[wiki/00-入口/四线闭环知识系统设计]] 发生变化；
- [[wiki/00-入口/动作型知识系统建设纲领]] 发生变化；
- [[wiki/70-审查协议/政府采购招标文件业务审查流水线]] 发生变化；
- [[wiki/20-知识点/政府采购招标文件画像]] 的画像字段发生变化；
- [[wiki/20-知识点/知识分层与路由规则]] 的路由顺序、适用层级或必读知识发生变化；
- [[wiki/20-知识点/政府采购逐章审查矩阵]] 的章节或必查项发生变化；
- 新增、删除或重命名品类动作协议；
- 品类动作协议中的必做动作发生新增、删除、重命名或含义调整；
- [[wiki/70-审查协议/风险原子化规则]] 的拆分规则或输出字段发生变化；
- [[wiki/70-审查协议/质量门规则]] 的质量门项目、通过条件或失败处理发生变化；
- [[wiki/90-模板/审查记录模板]] 或 [[wiki/90-模板/AI调度运行记录模板]] 的字段发生变化；
- 外部执行主体的权限边界、禁止事项或初始化成功标准发生变化；
- 中间产物编号、名称、字段或通过条件发生变化。

### 13.2 通常不需要更新本指引的变化

以下变化通常不需要更新本指引，只需要更新被引用知识页：

- 某个风险审查点补充典型原文；
- 某个法规依据页面补充来源、条文或摘要；
- 某个项目审查记录更新；
- 某个语料样本增加；
- 某个风险点修改建议优化；
- 某个具体项目的人工复盘补充；
- 不改变执行流程、字段、动作或质量门的文字润色。

### 13.3 判断标准

判断是否更新本指引时，只问一个问题：

```text
这次知识变化，是否会影响外部执行主体怎么读取知识、怎么生成动作、怎么产出中间产物、怎么执行质量门或怎么输出报告？
```

如果答案是“是”，本指引必须同步更新，或至少在知识更新申请中标记为 `待确认`。

### 13.4 知识更新申请要求

凡是知识更新申请涉及以下内容，必须填写“外部执行主体指引影响评估”：

- 画像字段；
- 知识路由；
- 动作协议；
- 逐章矩阵；
- 风险原子化；
- 质量门；
- 审查记录模板；
- 运行记录模板；
- 外部执行主体权限边界；
- 初始化成功标准。

建议字段：

```text
是否影响外部执行主体指引:: 是/否/待确认
影响类型:: 画像字段/路由规则/动作协议/逐章矩阵/风险原子化/质量门/输出模板/权限边界/初始化标准
是否需要更新本指引:: 是/否/待确认

```
