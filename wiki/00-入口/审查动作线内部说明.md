## 1. 这条线解决什么问题

审查动作线解决的是：知识供给线准备好的知识，如何变成一套能真实审查政府采购招标文件的动作流程。

外部执行主体不能只读取知识后自由总结。它必须按固定动作执行：

```text
输入文件
  -> 文件画像
  -> 知识路由
  -> 动作清单
  -> 逐动作执行
  -> 风险原子化
  -> 质量门反查
  -> AI审查记录
  -> 运行记录
```

审查动作线回答：

- 收到一份招标文件后先做什么；
- 如何建立文件画像；
- 如何根据画像选择知识；
- 如何把知识转成动作清单；
- 如何逐章读取公告、需求、评分和合同；
- 如何识别存在型风险和缺失型风险；
- 如何拆分风险；
- 如何执行质量门；
- 如何输出可读审查记录和可审计运行记录。

一句话：审查动作线把“知识”变成第 4 条线能够复现的“审查动作”。

## 2. 标准输入边界

审查动作线的输入是政府采购采购文件，通常包括：

- 招标文件；
- 公告；
- 采购需求或用户需求书；
- 评分办法；
- 合同条款；
- 投标文件格式；
- 附件、补充文件、答疑文件；
- 抽取后的纯文本。

执行前必须确认：

| 检查项 | 要求 |
| --- | --- |
| 文件可读性 | 能读取主要文字、表格和附件 |
| 文件属性 | 属于政府采购采购文件或可疑似识别为采购文件 |
| 原文保护 | 不编辑、不覆盖 `raw/` 原始文件 |
| 审查口径 | AI 审查只使用本库材料和明确引用的依据 |
| 外部标注 | 不使用 V2、标准答案或人工批注反推风险 |

如果文件无法读取，应生成失败说明，不得编造画像或风险。

## 3. 环节一：文件画像

文件画像是审查动作线的起点。画像不是摘要，而是决定后续知识路由和动作清单的业务判断。

### 3.1 画像目标

画像必须回答：

- 这是不是政府采购文件；
- 是什么采购方式；
- 评审方法是什么；
- 采购标的是什么；
- 标的属性和所属行业是什么；
- 适用哪个地域规则；
- 命中什么品类和场景；
- 文件章节是否完整；
- 哪些字段缺失；
- 哪些风险入口需要重点审查。

### 3.2 必填字段

`01-文件画像` 至少包含：

```text
项目编号::
项目名称::
采购人::
代理机构::
采购方式::
评审方法::
预算金额::
最高限价::
采购品目::
采购标的::
标的属性::
标的所属行业::
适用地域::
交易平台::
是否专门面向中小企业::
是否接受联合体::
是否允许分包::
是否允许进口产品::
场景标签::
文件章节清单::
初步风险入口::
画像置信度::
待确认项::
```

### 3.3 画像结果如何影响后续动作

| 画像结果 | 后续影响 |
| --- | --- |
| 深圳项目 | 路由深圳地方政府采购规则 |
| 公开招标 | 路由货物和服务招标投标管理办法相关审查 |
| 服务类采购 | 重点审查人员、方案、合同、履约和政策功能 |
| 物业管理 | 路由物业管理动作化审查包和物业动作协议 |
| 学校、医院、法院场景 | 路由对应专项风险入口 |
| 标的所属行业缺失 | 触发中小企业政策和所属行业缺失类风险检查 |
| 合同章节缺失 | 触发合同关键空白和模板错配检查 |

## 4. 环节二：知识路由

知识路由把画像结果转成“本次审查要调用哪些知识”。

固定顺序：

```text
全国通用规则
  -> 地方规则
  -> 采购方式规则
  -> 标的属性规则
  -> 品类规则
  -> 场景规则
  -> 章节规则
  -> 风险审查点
  -> 模板和质量门
```

### 4.1 路由产物

`02-知识路由表` 至少包含：

```text
画像字段
命中规则
调用知识页
调用原因
适用层级
适用地域
适用品类或场景
是否必读
执行状态
未调用原因
```

### 4.2 必须调用的通用知识

无论品类如何，必须调用：

## 5. 环节三：动作清单生成

动作清单把知识路由结果转成“本次必须做什么”。

动作不得由模型自由编造，应来自：

- 政府采购逐章审查矩阵；
- 政府采购招标文件审查协议；
- 命中品类动作协议；
- 命中风险审查点；
- 缺失类风险审查；
- 质量门要求。

### 5.1 动作清单字段

`03-动作清单` 至少包含：

```text
动作ID
动作名称
来源知识
必读章节
触发信号
必须检查
排除条件
预期输出
关联风险审查点
是否必做
执行状态
未执行原因
```

### 5.2 动作类型

| 动作类型 | 说明 | 示例 |
| --- | --- | --- |
| 画像动作 | 抽取项目基本信息和业务属性 | 预算金额、采购方式、所属行业 |
| 章节动作 | 按章节检查 | 公告、需求、评分、合同 |
| 风险动作 | 检查某类风险 | 人员证书、业绩、认证、本地化 |
| 缺失动作 | 检查应写未写 | 合同付款、验收标准、所属行业 |
| 质量动作 | 定稿前反查 | 原文证据、风险拆分、异常低风险数量 |

## 6. 环节四：逐章逐动作执行

逐动作执行用于证明审查不是摘要式判断，而是按动作清单读取原文。

### 6.1 逐动作执行字段

`04-动作执行记录` 至少包含：

```text
动作ID
动作名称
执行状态：命中 / 未命中 / 待确认 / 不适用
读取章节
读取范围
原文位置
原文摘录
命中信号
初步判断
关联审查点
是否形成候选风险
待确认原因
```

### 6.2 章节覆盖

最低覆盖范围：

| 章节 | 必查重点 |
| --- | --- |
| 招标公告 | 项目属性、资格条件、预算、采购方式、联合体、中小企业政策 |
| 投标人须知 | 投标规则、无效投标、分包、分公司、关联主体 |
| 资格审查 | 资格条件是否过度或违法 |
| 符合性审查 | 实质性响应和投标无效条款是否扩大化 |
| 采购需求 | 服务范围、技术参数、人员配置、费用边界、验收考核 |
| 评分办法 | 价格、方案、人员、认证、业绩、荣誉、承诺、软著 |
| 证明材料 | 社保、截图、原件备查、合同关键页、证书材料 |
| 合同条款 | 服务范围、付款、验收、违约、模板错配、交接责任 |
| 投标格式 | 声明函、承诺函、报价表、资格证明 |

没有发现风险的章节，也要记录已读范围和未命中说明。

## 7. 存在型风险和缺失型风险

政府采购招标文件审查不能只找“写出来的问题”。有些风险来自文件应写未写。

### 7.1 存在型风险

文件中出现某些条款，经判断构成风险。

示例：

- 项目负责人评分过度绑定学历、职称和职业资格；
- 要求本地服务网点或近场住宿；
- 同类业绩限定过窄；
- 体系认证范围被特定化；
- 合同条款与采购需求不一致；
- 方案类评分主观裁量过大。

### 7.2 缺失型风险

文件中未见应当明确的内容，也可能形成风险。

示例：

- 未明确预算金额或最高限价；
- 未明确采购标的所属行业；
- 未明确付款方式和支付时限；
- 未明确验收标准；
- 合同模板关键空白；
- 未明确是否接受联合体或分包；
- 中小企业政策适用口径缺失。

缺失型风险必须写明：

- 已读哪些章节；
- 应出现在哪里；
- 未见什么字段；
- 为什么该缺失影响合规审查或执行。

## 8. 环节五：风险原子化

风险原子化把候选风险拆成审查人员能逐条理解、逐条整改、逐条复核的问题。

### 8.1 原子风险字段

`05-原子风险清单` 至少包含：

```text
风险ID
来源动作ID
风险标题
结论类型
风险等级
原文位置
原文内容
问题说明
关联审查点
审查依据
修改建议
是否需人工复核
合并或拆分说明
```

### 8.2 字段边界

- `原文内容` 只放招标文件原文或明确缺失事实；
- `问题说明` 写风险成立理由；
- `来源动作ID` 说明是哪个动作发现；
- `关联审查点` 指向稳定风险审查点；
- `审查依据` 放法规、知识点、风险模式或协议；
- `修改建议` 必须可执行。

### 8.3 必须拆分的情形

以下不得合并成一个大风险：

- 人员证书组合和社保时点；
- 人员证书组合和证明材料负担；
- 用户需求人员限制和评分人员证书；
- 体系认证和供应商资质；
- 业绩范围和业绩证明材料；
- 合同模板错配和付款验收违约空白；
- 承诺函评分和合同条款不清；
- 供应商认证、资质、荣誉、业绩、软著等不同能力证明。

## 9. 环节六：质量门反查

质量门决定报告是否允许定稿。

`06-质量门检查表` 至少包含：

```text
质量门ID
检查项
检查结果：通过 / 未通过 / 待确认
发现问题
回退环节
处理动作
复查结果
```

### 9.1 最低质量门

必须检查：

- 文件画像完整性；
- 知识路由完整性；
- 动作清单完整性；
- 逐动作执行完整性；
- 逐章覆盖完整性；
- 原文证据完整性；
- `原文内容` 字段纯净性；
- 风险原子化完整性；
- 缺失类风险检查；
- 人员评分反查；
- 供应商能力评分反查；
- 用户需求书反查；
- 合同条款反查；
- 方案和承诺评分反查；
- 异常低风险数量反查；
- 待确认项清单。

### 9.2 质量门失败处理

质量门不通过时：

1. 回到缺失动作；
2. 补读原文；
3. 重新判断命中、未命中或待确认；
4. 必要时拆分风险；
5. 更新原子风险清单；
6. 更新运行记录；
7. 再次执行质量门。

## 10. 环节七：输出双记录

审查动作线最终输出两类正式产物。

| 输出 | 作用 |
| --- | --- |
| AI审查记录 | 给业务审查人员阅读，呈现画像、风险点、原文内容、问题说明和修改建议 |
| 运行记录 | 给系统审计和流程复现使用，记录知识、动作、中间产物和质量门 |

### 10.1 AI审查记录至少包含

- 项目基本信息；
- 文件画像摘要；
- 知识路由摘要；
- 动作执行摘要；
- 风险点清单；
- 已审查未列风险；
- 待补证或待确认；
- 质量门结论；
- 文件位置。

### 10.2 运行记录至少包含

- 执行边界；
- 是否使用外部标注；
- 必读知识清单；
- 知识路由表；
- 中间产物清单；
- 文件画像；
- 动作清单和执行状态；
- 原文读取记录；
- 原子风险清单摘要；
- 质量门结果；
- 未命中动作说明；
- 待人工复核事项；
- 模型调用或工具调用说明；
- 是否修改知识库。

## 11. 如何支撑第 4 条线

第 4 条线要复现审查动作，依赖本线提供：

| 第 4 条线需要 | 审查动作线提供 |
| --- | --- |
| 收到文件后怎么开始 | 文件画像和输入边界 |
| 读哪些知识 | 知识路由 |
| 做哪些检查 | 动作清单 |
| 如何证明读过原文 | 逐动作执行记录 |
| 如何拆风险 | 风险原子化规则 |
| 如何防漏报误报 | 质量门 |
| 如何输出 | AI审查记录和运行记录 |

审查动作线的成熟程度，直接决定外部执行主体能否稳定输出政府采购招标文件合规审查结果。
