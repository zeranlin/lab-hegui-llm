## 1. 这条线解决什么问题

知识供给线解决的是：为了让外部执行主体能够审查政府采购招标文件，本知识库必须先准备哪些知识、如何组织这些知识、如何让这些知识可读取、可路由、可判断、可输出。

外部执行主体最终只看到“入口协议”和“审查动作”，但这些动作背后必须有稳定知识支撑。没有知识供给线，第 4 条线会变成模型自由发挥。

知识供给线回答：

- 什么内容算政府采购招标文件合规审查知识；
- 原始材料如何进入 `raw/` 和 `wiki/`；
- 法规、行业基础、知识点、风险审查点、风险库分别承担什么角色；
- 一个风险审查点如何从经验判断变成可执行规则；
- 元数据如何支持地域、采购方式、品目、场景和章节路由；
- 哪些知识变化会影响外部执行主体入口协议；
- 如何判断知识是否足够驱动审查动作。

一句话：知识供给线为第 4 条线准备“执行器能读懂、能选择、能使用”的政府采购审查知识。

## 2. 什么内容才算知识

本库中的知识不是泛泛资料。只有能够影响审查动作、判断边界、输出字段或复盘回写的内容，才算稳定知识。

可以入库的知识：

| 知识类型 | 判断标准 | 示例 |
| --- | --- | --- |
| 行业对象知识 | 能帮助识别政府采购文件、采购方式、采购品目和参与主体 | 政府采购主体、招标文件结构、采购方式 |
| 法规依据知识 | 能支撑风险判断或排除误报 | 政府采购法、87号令、需求管理办法、中小企业办法 |
| 审查动作知识 | 能告诉执行主体看哪里、找什么 | 文件画像、逐章审查矩阵、缺失类风险审查 |
| 风险判断知识 | 能判断某类条款是否构成风险 | 人员证书异常加分、本地化限制、合同空白 |
| 排除条件知识 | 能减少误报 | 合法必要的资质要求、特定场景的合理响应要求 |
| 原文样本知识 | 能作为证据样本或边界样本 | 典型风险条款、正常条款、缺失类样本 |
| 输出模板知识 | 能规范审查记录和运行记录 | 审查记录模板、AI调度运行记录模板 |
| 质量门知识 | 能决定报告是否允许定稿 | 动作完整性、证据完整性、异常低风险反查 |

不应进入稳定知识层的内容：

- 单个项目临时判断；
- 没有依据的经验性结论；
- 尚未复核的外部标注；
- 只适用于某一份文件且不能复用的措辞修改；
- 与政府采购招标文件合规审查无关的背景材料；
- 从标准答案或 V2 结果反推但没有经过 AI 审查和复盘隔离的结论。

## 3. 政府采购行业知识的业务边界

知识供给线必须始终围绕“政府采购行业招标文件合规性审查”，不能泛化成普通招投标、普通合同或普通项目管理知识。

### 3.1 审查对象

外部执行主体最终审查的是采购文件，重点包括：

- 招标公告；
- 投标人须知；
- 资格条件；
- 采购需求；
- 用户需求书；
- 政府采购政策；
- 评审因素和评分办法；
- 资格性审查和符合性审查；
- 投标文件格式和证明材料；
- 合同条款；
- 付款、验收、违约和考核条款。

### 3.2 审查目标

知识供给线沉淀的知识，应服务以下审查目标：

- 采购文件是否完整；
- 资格条件是否违法或过度；
- 采购需求是否完整、明确、可执行；
- 技术参数或服务要求是否指向特定供应商；
- 评审因素是否与采购需求相关；
- 评分办法是否合理、客观、可量化；
- 政府采购政策是否正确适用；
- 合同条款是否清晰、公平、与需求一致；
- 是否存在以不合理条件限制或排斥供应商；
- 是否存在缺失类风险。

## 4. 知识来源和入库路径

知识供给线从四类来源生成知识。

| 来源 | 落点 | 处理方式 |
| --- | --- | --- |
| 原始法规和政策 | `raw/法规/`; `wiki/10-法规依据/` | 保留来源，提炼审查规则和适用边界 |
| 原始招标文件 | `raw/招标文件/`; `wiki/50-语料与摘录/` | 保留不可变原文，抽取章节、条款和典型样本 |
| 项目审查记录 | `wiki/40-审查工作台/审查记录/` | 只作为项目结论，不能直接当稳定知识 |
| 人工复盘和知识更新申请 | `wiki/40-审查工作台/人工调整复盘/`; `wiki/40-审查工作台/知识更新申请/` | 判断是否可复用，再回写知识点、风险审查点或协议 |

标准路径：

```text
原始材料
  -> 来源笔记和摘录
  -> 业务事实抽取
  -> 法规和行业归类
  -> 判断规则沉淀
  -> 风险审查点或知识点
  -> 动作协议和质量门
  -> 外部执行主体可读取知识
```

## 5. 知识分层如何支撑第 4 条线

第 4 条线需要按顺序读取知识，因此知识供给线必须保持清晰分层。

| 层级 | 目录 | 给第 4 条线提供什么 |
| --- | --- | --- |
| 入口层 | `wiki/00-入口/` | 系统目标、四线关系、外部执行入口 |
| 法规层 | `wiki/10-法规依据/` | 风险判断的权威依据和适用边界 |
| 行业基础层 | `wiki/15-行业基础/` | 政府采购行业、品目、场景和文件结构 |
| 知识点层 | `wiki/20-知识点/` | 文件画像、逐章矩阵、缺失类风险、判断框架 |
| 风险审查点层 | `wiki/25-风险审查点/` | 可执行的风险触发条件、判断规则和排除条件 |
| 风险模式层 | `wiki/30-风险库/` | 跨项目、跨品类的风险表达和归类 |
| 项目工作层 | `wiki/40-审查工作台/` | 审查样本、运行记录、复盘和更新申请 |
| 语料摘录层 | `wiki/50-语料与摘录/` | 招标文件原文证据、典型条款和边界样本 |
| 提示词层 | `wiki/60-提示词/` | 将知识转成 AI 可执行任务 |
| 审查协议层 | `wiki/70-审查协议/` | 把知识变成动作和质量门 |
| 模板层 | `wiki/90-模板/` | 固定审查记录、运行记录、复盘和更新字段 |

第 4 条线读取这些知识时，不是平均读取，而是先读入口和通用规则，再根据画像路由地域、采购方式、品类、场景和风险审查点。

## 6. 元数据如何设计

政府采购审查特别依赖适用范围。一个知识点是否可用，不只看它“是否正确”，还要看它适用于哪个地域、采购方式、品目、场景和时间。

建议稳定知识页至少包含：

```text
类型::
主题::
状态::
效力层级::
适用地域::
适用采购方式::
适用品目或场景::
适用章节::
风险类型::
风险等级::
依据来源::
关联法规::
关联知识点::
关联风险审查点::
生效日期::
失效日期::
复核状态::
权限级别::
```

### 6.1 状态字段

| 状态 | 含义 | 是否可驱动第 4 条线 |
| --- | --- | --- |
| 草稿 | 初步整理，未经复核 | 否 |
| 待复核 | 已形成规则但边界不清 | 可提示，不宜直接定性 |
| 试运行 | 可用于 AI 审查，但需记录复核 | 可用，需留痕 |
| 有效 | 已可稳定驱动审查 | 可用 |
| 地域待核 | 可能受地方规则影响 | 需结合地域路由 |
| 冲突待处理 | 与其他知识存在冲突 | 不得直接用于定稿 |
| 废止 | 失效或不再适用 | 不得调用 |

### 6.2 权限字段

| 权限级别 | 含义 |
| --- | --- |
| 只读 | 外部执行主体可读取，不得修改 |
| 维护人可改 | 需由知识维护人修改 |
| 复核后生效 | 修改后必须经过复核才能驱动正式审查 |
| 项目记录 | 只用于项目审查，不作为稳定知识 |

## 7. 风险审查点如何从经验变成可执行规则

风险审查点是第 4 条线识别风险的核心知识单元。

一个风险审查点至少要回答：

```text
适用范围是什么？
从招标文件哪里找？
什么原文信号可能触发？
什么条件下风险成立？
什么条件下不成立？
常见原文是什么？
常见误报是什么？
关联哪些法规、知识点或风险模式？
输出风险标题怎么写？
原文内容字段怎么保留？
问题说明怎么写？
修改建议怎么写？
是否需要人工复核？
```

### 7.1 风险审查点字段

建议字段：

```text
类型:: 风险审查点
状态::
风险类型::
风险等级::
适用地域::
适用采购方式::
适用品目或场景::
适用章节::
识别信号::
成立条件::
排除条件::
常见原文::
常见误报::
关联法规::
关联知识点::
关联风险库::
推荐风险标题::
推荐修改建议::
质量门要求::
```

### 7.2 示例：人员证书异常加分

从经验判断到可执行规则的转换：

| 转换环节 | 内容 |
| --- | --- |
| 经验描述 | 项目负责人评分绑定学历、职称和职业资格，可能排斥供应商 |
| 审查位置 | 评分办法、人员配置要求、投标文件格式、证明材料要求 |
| 识别信号 | 学历、职称、职业资格、社保、证书组合、唯一人员绑定 |
| 成立条件 | 与采购需求关联不足，证书组合过度，证明材料负担明显 |
| 排除条件 | 法律法规明确要求，或岗位职责确有必要且评分适度 |
| 输出动作 | 形成独立风险，不与社保时点或证明材料过度要求混并 |
| 关联知识 | 人员学历职称证书异常加分、证明材料要求不清或过度 |

## 8. 知识如何被第 4 条线路由

第 4 条线不会一次性读取全部知识，而是根据文件画像路由。

固定路由顺序：

```text
全国通用规则
  -> 地方规则
  -> 采购方式规则
  -> 标的属性规则
  -> 品类规则
  -> 场景规则
  -> 章节规则
  -> 风险审查点
  -> 模板和质量门
```

知识供给线必须确保每个可路由知识都有清晰适用字段。

### 8.1 路由触发字段

| 画像字段 | 可能路由到 |
| --- | --- |
| 适用地域 | 全国规则、深圳地方规则、平台规则 |
| 采购方式 | 公开招标、磋商、谈判、询价相关规则 |
| 评审方法 | 综合评分法、最低评标价法等评分审查规则 |
| 标的属性 | 货物、服务、工程、混合采购 |
| 采购品目 | 物业管理、信息化设备等品类知识 |
| 场景标签 | 学校、医院、法院、机关、数据中心等专项场景 |
| 文件章节 | 公告、需求、评分、合同、格式对应审查矩阵 |
| 初步风险入口 | 资格、人员、认证、业绩、合同、中小企业等风险审查点 |

### 8.2 知识供给失败的表现

如果第 4 条线出现以下问题，通常说明知识供给线不足：

- 外部执行主体不知道该读哪些知识；
- 能识别风险，但无法关联稳定审查点；
- 能发现原文，但不知道是否构成风险；
- 风险标题不稳定；
- 原文内容和问题说明混杂；
- 不知道地方规则是否适用；
- 不知道何时排除误报；
- 不知道质量门应反查什么。

## 9. 知识质量门

知识供给线自身也需要质量门。不是所有写进 wiki 的内容都能驱动第 4 条线。

### 9.1 单页知识质量门

一页稳定知识至少应通过：

- 是否明确适用范围；
- 是否有来源或依据；
- 是否能说明用于哪个审查环节；
- 是否能转成“看哪里、找什么、怎么判断”；
- 是否有排除条件；
- 是否说明输出字段或修改建议；
- 是否链接到相关法规、知识点、风险审查点或模板；
- 是否标明状态和复核要求；
- 是否会影响外部执行主体入口协议。

### 9.2 知识包质量门

一个品类或专题知识包至少应具备：

- 行业背景；
- 文件画像规则；
- 相关法规和政策；
- 逐章审查矩阵；
- 风险审查点清单；
- 品类动作协议；
- 典型原文样本；
- 审查记录模板适配；
- 运行记录要求；
- 质量门；
- 人工复盘和更新入口。

## 10. 影响第 4 条线的变化

知识供给线发生以下变化时，必须评估是否同步更新 [[wiki/00-入口/外部执行主体招标文件审查指引]]：

- 新增或删除画像字段；
- 调整知识分层和路由顺序；
- 新增、删除或重命名品类动作协议；
- 风险审查点字段发生变化；
- 风险原子化规则变化；
- 质量门项目变化；
- 审查记录或运行记录模板字段变化；
- 权限、状态或地域适用规则变化；
- 新增会影响外部执行主体初始化成功标准的知识。

不影响第 4 条线的变化，通常只需更新对应知识页：

- 某个风险审查点补充典型原文；
- 某个法规页补充来源链接；
- 某个项目审查记录修正文案；
- 不改变执行流程的文字润色。

## 11. 知识供给线最小产物

为了支撑第 4 条线，一个专题知识包至少要产出：

```text
01 行业基础页
02 法规依据页或法规索引
03 招标文件画像规则
04 知识分层与路由规则
05 逐章审查矩阵
06 风险审查点清单
07 风险模式页
08 品类动作协议
09 质量门规则
10 审查记录模板
11 运行记录模板
12 人工复盘和知识更新模板
13 外部执行主体入口协议影响评估
```

如果缺少这些产物，第 4 条线即使能读取知识，也难以稳定复现政府采购招标文件合规审查。

## 12. 和其他三条线的关系

| 关系 | 说明 |
| --- | --- |
| 支撑审查动作线 | 提供画像字段、路由规则、风险审查点和模板，让审查动作线能生成动作 |
| 接收效果校准线回写 | 将人工复盘中的可复用结论沉淀为知识点、风险审查点、动作协议或质量门 |
| 服务外部执行线 | 提供外部执行主体必须读取和路由的知识 |
| 约束项目工作层 | 项目审查记录不能直接变成稳定知识，必须经过复盘和更新申请 |

因此，知识供给线的终点不是“资料整理完成”，而是“第 4 条线能够读取这些知识，并据此完成政府采购招标文件审查”。
