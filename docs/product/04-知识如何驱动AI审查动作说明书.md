# 知识如何驱动 AI 审查动作说明书

版本:: 1.0
状态:: 初稿
适用范围:: 政府采购招标文件合规审查知识系统

## 1. 文档目的

本文用于说明知识如何从静态内容变成 AI 审查动作，避免产品只做“知识检索 + 大模型总结”。

在本产品中，知识不是给 AI 参考一下，而是要约束 AI 看什么、按什么顺序看、依据什么判断、如何输出、如何接受人工复盘。

## 2. 总体驱动链路

知识驱动 AI 审查的完整链路为：

```text
待审招标文件
  -> 文件解析
  -> 项目画像
  -> 知识路由
  -> 逐章审查
  -> 风险判断
  -> 风险输出
  -> 人工复核
  -> 漏误报复盘
  -> 知识回写
```

其中，项目画像是路由器，知识路由是调度器，风险审查点是最小规则单元，人工复盘是精确率提升入口。

## 3. 知识驱动文件画像

AI 审查前必须先建立文件画像。文件画像不是摘要，而是决定调用哪些知识。

画像维度：

- 项目名称；
- 项目编号；
- 采购人；
- 代理机构；
- 采购方式；
- 评审方法；
- 预算金额；
- 采购品目；
- 标的属性；
- 所属行业；
- 适用地域；
- 是否专门面向中小企业；
- 是否接受联合体；
- 是否允许进口产品；
- 主要章节完整性；
- 初步风险入口。

示例：

```text
地域=深圳市
采购方式=公开招标
品目=物业管理
场景=医院物业
评审方法=综合评分法
  -> 调用全国政府采购规则
  -> 调用深圳地方政府采购规则
  -> 调用公开招标审查规则
  -> 调用物业管理审查包
  -> 调用医院物业场景规则
```

## 4. 知识驱动路由

知识路由解决“知识库变大后，AI 该用哪些知识”的问题。

路由顺序建议：

```text
全国通用规则
  -> 项目所在地规则
  -> 采购方式规则
  -> 标的属性规则
  -> 品类规则
  -> 场景规则
  -> 章节规则
  -> 试运行规则
```

路由不是简单关键词检索，而是根据画像标签精确调用。

产品需要记录：

- 本次审查调用了哪些知识；
- 哪些知识被命中；
- 哪些知识参与了风险判断；
- 哪些知识被人工认为不适用；
- 哪些知识需要调整适用范围。

## 5. 知识驱动逐章审查

政府采购招标文件有稳定章节结构，AI 应按章节审查，而不是整篇一次性总结。

典型章节和审查重点：

| 章节 | 审查重点 | 常见风险 |
| --- | --- | --- |
| 招标公告 | 预算、采购方式、资格要求、联合体、中小企业政策 | 资格过度、政策适用错误 |
| 投标人须知 | 实质性要求、投标无效、证明材料 | 无效条款扩大化、材料要求不清 |
| 资格条件 | 法定资格、特定资格、业绩、证书 | 限制排斥供应商 |
| 采购需求 | 服务范围、技术要求、人员配置、验收 | 需求不完整、指向性要求 |
| 评标办法 | 分值结构、评分因素、量化标准 | 评分脱节、主观裁量过大 |
| 政府采购政策 | 中小企业、节能环保、进口产品 | 政策落实错误 |
| 合同条款 | 付款、验收、违约、服务期 | 条款不清、与需求不一致 |
| 投标文件格式 | 承诺函、声明函、证明材料 | 格式和实质要求冲突 |

逐章审查矩阵应告诉 AI：

- 本章通常有哪些内容；
- 必查字段是什么；
- 应写未写如何判断；
- 可能触发哪些风险审查点；
- 结果应输出到哪里。

## 6. 知识驱动风险判断

风险判断不能只靠模型感觉，必须由风险审查点控制。

每个风险审查点应驱动 AI 完成：

```text
识别原文信号
  -> 判断是否满足风险成立条件
  -> 检查排除条件
  -> 判断风险等级
  -> 关联法规依据
  -> 生成修改建议
```

示例：

| 审查点 | 触发信号 | 判断边界 |
| --- | --- | --- |
| 本地化限制 | 本地注册、本地网点、近场响应、就近住宿 | 是否构成排斥外地供应商，是否有合理履约必要性 |
| 同类业绩过窄 | 指定区域、指定行业、指定金额、指定采购人业绩 | 是否与采购需求直接相关，是否过度缩小竞争 |
| 主观分档过大 | 方案优秀良好一般但无量化标准 | 是否细化量化，是否可客观评审 |

## 7. 知识驱动风险输出

风险输出要服务政府采购审查人员，而不是生成泛泛 AI 结论。

每条风险必须包含：

- 风险标题；
- 结论类型；
- 风险等级；
- 所属章节；
- 原文位置；
- 原文内容；
- 问题说明；
- 关联审查点；
- 审查依据；
- 修改建议；
- 是否需要人工复核；
- AI 置信度或审查状态。

字段边界：

| 字段 | 应写内容 | 不应写内容 |
| --- | --- | --- |
| 原文内容 | 招标文件直接摘录 | 不写推理和改写 |
| 问题说明 | 风险成立或需复核的理由 | 不替代原文 |
| 审查依据 | 法规、知识点、审查点 | 不写模糊依据 |
| 修改建议 | 可执行修订方向 | 不只写建议完善 |

## 8. 知识驱动人工复核

人工复核不是简单改报告，而是系统学习入口。

审查人员应能对 AI 风险执行：

- 确认；
- 驳回；
- 修改风险等级；
- 修改标题；
- 修改原文定位；
- 修改问题说明；
- 修改建议；
- 合并重复风险；
- 拆分复杂风险；
- 新增漏报风险；
- 标记争议项；
- 标记无需出报告。

每个动作应记录修改原因，并判断是否需要进入复盘。

## 9. 知识驱动回写

人工调整后的内容不能直接污染稳定知识库。应先分流：

```text
人工调整
  -> 是否可复用
    -> 否：项目个案备注
    -> 是：进入复盘
      -> 是否已有审查点
        -> 有：补充触发信号、排除条件、输出口径
        -> 无：申请新增风险审查点
      -> 复核通过后回写知识库
```

可回写内容：

- 新增风险审查点；
- 新增品类场景边界；
- 补充触发信号；
- 补充排除条件；
- 补充常见误报；
- 优化风险等级；
- 优化输出口径；
- 增加正例、反例、边界样本。

## 10. 产品经理判断

知识驱动 AI 审查的本质，是把大模型从“自由阅读者”变成“受知识约束的审查执行者”。产品价值不在于 AI 能不能读懂文件，而在于系统能否让 AI 按政府采购审查逻辑稳定地画像、路由、逐章检查、输出证据链，并通过人工复盘持续提升准确率。
