# 角色权限与状态流说明书

版本:: 1.0
状态:: 初稿
适用范围:: 政府采购招标文件合规审查知识作业平台

## 1. 文档目的

本文用于定义正式产品的角色、权限和核心状态流，确保政府采购审查知识、AI 审查任务、人工复核和知识回写都能被规范管理。

## 2. 角色设计

### 2.1 系统管理员

负责：

- 租户配置；
- 省份知识空间配置；
- 算力环境配置；
- 用户和角色配置；
- 流程配置；
- 安全策略配置。

### 2.2 省份管理员

负责：

- 本省知识包管理；
- 本省上线品类配置；
- 本省算力资源绑定；
- 本省用户权限；
- 本省审查规则发布协调。

### 2.3 知识维护人

负责：

- 新增知识草稿；
- 整理法规和语料；
- 补充触发信号；
- 提交知识更新申请；
- 维护 LLM + Wiki 样板内容。

### 2.4 业务审查人

负责：

- 上传待审文件；
- 查看 AI 审查结果；
- 确认、修改或驳回风险；
- 新增漏报风险；
- 提交人工复盘；
- 发起知识回写建议。

### 2.5 品类专家

负责：

- 复核品类审查包；
- 确认品类规则适用边界；
- 处理品类相关漏报误报；
- 判断项目经验是否可扩展为品类知识。

### 2.6 法规复核人

负责：

- 复核法规依据；
- 确认效力层级；
- 判断上位法和地方规则冲突；
- 确认风险结论是否有法规支撑。

### 2.7 地域复核人

负责：

- 复核省级、市级和平台规则；
- 确认本地规则适用范围；
- 判断其他省份经验是否可引入本地；
- 审核本地试运行规则。

### 2.8 知识管理员

负责：

- 知识发布；
- 知识废止；
- 知识版本回滚；
- 知识冲突处理；
- 维护知识目录和状态。

## 3. 权限原则

- AI 可以生成候选知识，但不能发布有效知识；
- 业务审查人可以修改项目结果，但不能直接修改有效知识；
- 知识维护人可以编辑草稿，但不能直接发布；
- 品类规则由品类专家复核；
- 地方规则由地域复核人复核；
- 法规依据由法规复核人复核；
- 跨省知识引入必须经过目标省份确认；
- 省份算力和数据默认隔离。

## 4. 知识状态流

```text
草稿 -> 待复核 -> 试运行 -> 有效 -> 废止
```

状态说明：

| 状态 | 含义 | 是否驱动正式审查 |
| --- | --- | --- |
| 草稿 | 初步整理，未经复核 | 否 |
| 待复核 | 已形成规则，等待专家或法规确认 | 仅提示 |
| 试运行 | 可用于审查，但需观察误报漏报 | 是，需标记 |
| 有效 | 已复核，可正式使用 | 是 |
| 废止 | 已失效或被替代 | 否 |

## 5. 审查任务状态流

```text
待解析 -> 解析中 -> 待画像 -> 画像中 -> 待审查 -> 审查中 -> 待人工复核 -> 已完成 -> 已归档
```

异常状态：

- 解析失败；
- 画像失败；
- 审查失败；
- 需补充文件；
- 人工退回重审。

## 6. 风险项状态流

```text
AI 识别 -> 待复核 -> 已确认 -> 已修改 -> 已驳回 -> 已出报告
```

特殊状态：

- 需人工确认；
- 项目个案；
- 不出报告；
- 待合并；
- 待拆分；
- 争议项。

## 7. 知识更新申请状态流

```text
草稿 -> 已提交 -> 待品类复核/待地域复核/待法规复核 -> 通过 -> 已回写 -> 已验证
```

退回状态：

- 退回补充证据；
- 暂缓；
- 驳回；
- 转项目个案；
- 转试运行。

## 8. 省份上线状态流

```text
准备中 -> 知识初始化 -> 算力配置 -> 品类包启用 -> 试运行 -> 正式上线 -> 持续运营
```

示例：

- 福建上线物业品目：先初始化福建知识包和福建算力，再启用物业审查包；
- 四川上线计算机品目：先初始化四川知识包和四川算力，再启用计算机设备审查包。

## 9. 审计留痕

必须记录：

- 知识变更；
- 状态变更；
- 版本发布；
- 审查任务调用知识；
- AI 输出结果；
- 人工修改；
- 回写审批；
- 跨省知识引入；
- 算力环境调用。

## 10. 产品经理结论

角色权限和状态流不是后台管理细节，而是政府采购审查产品可信运行的基础。尤其在多省份、本地算力和品类包差异化上线模式下，权限、状态和审计必须从产品第一期就纳入设计。
