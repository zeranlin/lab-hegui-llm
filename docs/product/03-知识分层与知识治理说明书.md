# 知识分层与知识治理说明书

版本:: 1.0
状态:: 初稿
适用范围:: 政府采购招标文件合规审查知识系统

## 1. 文档目的

本文用于说明政府采购招标文件合规审查知识如何分层、如何管理状态、如何控制适用范围、如何审核发布，以及如何从项目复盘回写为稳定知识。

知识分层解决“知识放哪里、怎么被调用”的问题；知识治理解决“知识是否可信、谁能改、什么时候生效”的问题。

## 2. 分层原则

政府采购知识不能全部放在一个知识库里。原因是：

- 法规、审查规则、品类经验、语料样本的稳定性不同；
- 国家规则、地方规则、平台规则的效力边界不同；
- 物业、信息化、医疗设备等品类的风险重点不同；
- 项目复盘经验未经确认前不能直接驱动正式审查。

因此知识分层应遵循：

- 越上层越稳定，越下层越贴近业务项目；
- 稳定知识驱动正式审查，项目经验先进入复盘和申请；
- 目录用于组织，元数据用于精确路由；
- 风险审查点是 AI 审查调用的最小稳定规则单元。

## 3. 建议知识分层

### 3.1 法规政策层

定位：权威依据层。

内容：

- 法律、行政法规、财政部规章、规范性文件；
- 地方性法规、地方财政政策；
- 集采目录、限额标准、平台规则；
- 专项政策，如中小企业、节能环保、进口产品。

管理重点：

- 来源可靠；
- 效力层级清楚；
- 生效、失效时间清楚；
- 地域适用清楚；
- 不直接写成风险结论。

### 3.2 行业基础层

定位：政府采购语境层。

内容：

- 政府采购主体和职责；
- 采购方式；
- 招标文件结构；
- 质疑投诉机制；
- 采购品目和标的属性；
- 发布前审查、内控审查和监管辅助场景。

管理重点：

- 帮助 AI 理解文件和业务背景；
- 作为文件画像和知识路由的基础。

### 3.3 审查知识点层

定位：审查动作层。

内容：

- 资格条件审查；
- 采购需求审查；
- 评分办法审查；
- 合同条款审查；
- 政府采购政策审查；
- 采购需求、评分、合同、验收闭环；
- 逐章审查矩阵。

管理重点：

- 每个知识点都要能回答看哪里、找什么、怎么判断；
- 用于驱动逐章审查，而不是泛泛解释概念。

### 3.4 风险审查点层

定位：最小规则单元。

内容：

- 本地化限制；
- 同类业绩限定过窄；
- 人员年龄性别身高形象限制；
- 供应商资质证书异常加分；
- 方案类评分主观裁量过大；
- 评审因素与采购需求脱节；
- 符合性审查和投标无效条款扩大化。

管理重点：

- 适用范围明确；
- 触发信号明确；
- 判断规则明确；
- 排除条件明确；
- 常见误报明确；
- 输出口径明确。

### 3.5 风险模式层

定位：跨项目风险归类层。

内容：

- 限制排斥供应商；
- 技术参数指向性；
- 评分因素不当；
- 业绩奖项限制；
- 本地化限制；
- 政策适用错误。

管理重点：

- 用于风险归类、报告统计和跨品类分析；
- 不替代具体风险审查点。

### 3.6 品类场景层

定位：行业差异层。

内容：

- 物业管理审查包；
- 信息化设备审查包；
- 医疗设备审查包；
- 工程相关服务审查包；
- 学校、医院、法院机关、建筑机电等细分场景。

管理重点：

- 同一规则在不同品类下有不同边界；
- 品类审查包决定 AI 审查重点和误报排除条件。

### 3.7 语料样本层

定位：真实表达层。

内容：

- 原始招标文件摘录；
- 典型风险条款；
- 正常条款；
- 边界条款；
- 历史投诉或整改样本。

管理重点：

- 保留来源；
- 标记正例、反例、边界样本；
- 关联风险审查点。

### 3.8 人工复盘层

定位：质量提升层。

内容：

- 人工调整记录；
- 漏报复盘；
- 误报复盘；
- 争议项复盘；
- 知识更新申请。

管理重点：

- 不能直接驱动正式审查；
- 经复核后才能回写到稳定知识层。

## 4. 知识元数据

正式产品中，每条知识至少应有以下元数据：

| 字段 | 说明 |
| --- | --- |
| 知识类型 | 法规、知识点、风险审查点、语料、复盘等 |
| 状态 | 草稿、待复核、试运行、有效、废止 |
| 效力层级 | 国家、省级、市级、平台、品类、项目 |
| 适用地域 | 全国、广东省、深圳市或其他地域 |
| 适用采购方式 | 公开招标、磋商、谈判、询价、框架协议等 |
| 适用品目 | 物业、信息化、医疗设备等 |
| 适用场景 | 学校、医院、法院机关、建筑机电等 |
| 适用章节 | 公告、资格、需求、评分、合同等 |
| 触发信号 | AI 召回该知识的原文线索 |
| 排除条件 | 降低误报的边界 |
| 关联依据 | 法规、政策、案例、项目样本 |
| 复核角色 | 谁有权确认其生效 |
| 版本 | 当前版本及历史版本 |

## 5. 知识状态流

建议状态流：

```text
草稿 -> 待复核 -> 试运行 -> 有效 -> 废止
```

特殊处理：

- `草稿`：只能整理和讨论，不驱动审查；
- `待复核`：可作为提示，不输出确定风险；
- `试运行`：可驱动 AI 审查，但结果需重点人工复核；
- `有效`：可进入正式审查流程；
- `废止`：不得再被正式审查调用。

## 6. 地域和层级治理

政府采购规则具有明显地域和层级特征。知识治理必须处理：

- 全国通用规则；
- 省级补充规则；
- 市级地方规则；
- 平台操作规则；
- 采购人内控制度；
- 品类经验规则。

冲突处理原则：

```text
上位法禁止性规定
  > 地方补充规则
  > 平台操作规则
  > 品类经验
  > 项目复盘经验
```

当规则冲突或适用不明时，系统应输出“需人工复核”，不能直接定性。

## 7. 知识权限

建议角色：

| 角色 | 权限 |
| --- | --- |
| 知识维护人 | 新增草稿、整理语料、提交更新申请 |
| 业务审查人 | 使用知识审查项目、提交人工复盘 |
| 品类专家 | 复核品类和场景规则 |
| 法规复核人 | 复核法规依据和效力边界 |
| 地域复核人 | 复核地方规则和平台规则 |
| 知识管理员 | 发布、废止、回滚知识版本 |
| 系统管理员 | 管理角色、目录、流程配置 |

AI 可以生成候选知识，但不能直接发布有效知识。

## 8. 知识治理指标

建议关注：

- 有效知识数量；
- 试运行知识转有效比例；
- 知识被审查任务调用次数；
- 知识命中后被人工确认比例；
- 知识导致误报次数；
- 知识导致漏报补充次数；
- 知识更新申请通过率；
- 废止或替代知识数量。

## 9. 产品经理判断

知识分层决定系统能否精准调用，知识治理决定系统能否可信运行。政府采购招标文件审查产品的壁垒，不只是有多少法规和案例，而是能否把这些知识管理成可执行、可审核、可追溯、可迭代的审查能力。
