# 人工调整与精确率提升产品说明书

版本:: 1.0
状态:: 初稿
所属产品线:: 人工调整和精确率提升线

## 1. 产品线定位

人工调整与精确率提升线负责管理审查人员对 AI 审查结果的复核、修改、漏报补充、误报删除和知识回写。

它回答三个问题：

- 审查人员怎么改 AI 结果；
- 漏报和误报怎么复盘；
- 哪些内容能回写知识库，让系统下一次更准。

## 2. 核心原则

### 2.1 人工不是补丁，而是学习来源

人工调整不应只停留在项目报告里。所有有复用价值的调整，都应进入复盘和知识更新流程。

### 2.2 AI 结果不能直接等于最终结论

政府采购审查具有合规责任，AI 输出必须经过人工确认或按规则进入需复核状态。

### 2.3 项目个案不能直接污染知识库

单个项目特殊判断、采购人偏好或未验证经验，不能直接进入有效知识。

## 3. 人工复核操作

审查人员可对风险项执行：

- 确认风险；
- 驳回风险；
- 修改风险等级；
- 修改风险标题；
- 修改原文定位；
- 修改问题说明；
- 修改审查依据；
- 修改整改建议；
- 合并重复风险；
- 拆分复杂风险；
- 新增漏报风险；
- 标记争议项；
- 标记项目个案；
- 标记不出报告。

## 4. 修改留痕

每一次人工修改都应记录：

- 修改人；
- 修改时间；
- 修改前内容；
- 修改后内容；
- 修改类型；
- 修改理由；
- 是否可复用；
- 是否建议知识回写；
- 关联原文；
- 关联知识或审查点。

## 5. 漏报复盘

漏报指 AI 未发现但人工认为应输出的风险。

漏报原因分类：

| 原因 | 说明 |
| --- | --- |
| 知识缺失 | 当前知识库没有对应规则 |
| 召回失败 | 有规则但未被路由或命中 |
| 画像错误 | 地域、品类、场景识别错误 |
| 章节识别错误 | 原文未被放入正确章节 |
| 表格解析失败 | 评分表、资格表等未正确抽取 |
| 判断失败 | AI 命中规则但未判定风险 |
| 输出失败 | 识别到问题但未形成风险项 |
| 品类边界缺失 | 规则没有覆盖当前品类场景 |

## 6. 误报复盘

误报指 AI 输出了风险，但人工认为不成立或不应出报告。

误报原因分类：

| 原因 | 说明 |
| --- | --- |
| 适用范围错误 | 规则不适用于当前省份、品类或场景 |
| 排除条件缺失 | 应排除的情况未被规则覆盖 |
| 原文理解错误 | AI 对条款语义理解不准 |
| 地方规则误用 | 使用了其他省份或平台规则 |
| 风险等级过高 | 风险成立但等级不应过高 |
| 输出口径过度 | 表述过于确定或不够审慎 |
| 项目特殊情况 | 当前项目有合理履约必要性 |

## 7. 知识回写规则

可回写：

- 新增风险审查点；
- 补充触发信号；
- 补充排除条件；
- 补充常见误报；
- 新增品类场景边界；
- 新增地方适用口径；
- 优化风险等级规则；
- 优化输出口径；
- 新增正例、反例、边界样本；
- 修改提示词或审查编排。

不可直接回写：

- 单个采购人的偏好；
- 未经确认的专家个人判断；
- 与法规冲突的经验；
- 只影响当前项目的措辞修改；
- 无原文证据的判断；
- AI 自动总结但未复核的规则。

## 8. 回写流程

```text
人工修改
  -> 判断是否可复用
  -> 创建复盘记录
  -> 创建知识更新申请
  -> 选择目标知识层
  -> 品类/地域/法规复核
  -> 进入草稿、待复核、试运行或有效状态
  -> 后续项目验证效果
```

## 9. 省份和品类维度

复盘必须记录省份和品类：

- 福建物业项目的漏报，应优先回写福建物业规则或全国物业规则；
- 四川计算机项目的误报，应优先检查四川规则、计算机品类包和全国通用规则；
- 本地规则不得无审查地回写到全国规则；
- 品类特殊经验不得无审查地扩展到所有品类。

## 10. 质量指标

- AI 风险确认率；
- AI 风险驳回率；
- 漏报数量；
- 误报数量；
- 风险等级调整率；
- 原文定位修改率；
- 修改建议重写率；
- 知识更新申请数量；
- 知识更新申请通过率；
- 回写后同类问题复发率；
- 省份知识包准确率；
- 品类审查包成熟度。

## 11. 产品经理结论

人工调整线是产品从“AI 工具”走向“知识作业系统”的关键。政府采购审查经验大量存在于人工判断中，产品必须把这些判断沉淀为可治理、可复核、可属地化、可品类化的知识。
