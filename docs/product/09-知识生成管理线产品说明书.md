# 知识生成管理线产品说明书

版本:: 1.0
状态:: 初稿
所属产品线:: 政府采购招标文件审查知识生成管理线

## 1. 产品线定位

知识生成管理线负责管理政府采购招标文件合规审查所需的全部知识资产。

它回答四个问题：

- 知识是什么；
- 知识放哪里；
- 知识状态怎么管；
- 谁能新增、修改、审核、发布和废止知识。

本产品线不是普通资料库，而是 AI 审查主流程的知识底座。

## 2. 管理对象

### 2.1 法规政策

包括国家、省、市、平台等层级的法规、规章、规范性文件、集采目录、限额标准和本地审查口径。

### 2.2 审查知识点

包括资格条件、采购需求、评分办法、政府采购政策、合同条款、采购方式、质疑投诉视角等审查知识。

### 2.3 风险审查点

作为 AI 审查的最小稳定规则单元，包含适用范围、触发信号、判断规则、排除条件、常见误报和输出口径。

### 2.4 品类审查包

按品类组织知识，例如：

- 物业管理审查包；
- 计算机设备审查包；
- 信息化设备审查包；
- 医疗设备审查包；
- 工程相关服务审查包。

### 2.5 地域知识包

按省份、市级和平台组织知识，例如：

- 全国通用知识包；
- 福建省知识包；
- 四川省知识包；
- 深圳市知识包；
- 某省交易平台知识包。

### 2.6 语料样本

包括真实招标文件原文、典型风险条款、正常条款、边界样本、历史复盘样本。

### 2.7 提示词和审查编排

包括画像提示词、章节抽取提示词、风险审查提示词、复盘提示词和知识回写提示词。

## 3. 知识来源

知识来源包括：

- 法规政策采集；
- 地方条款整理；
- 交易平台规则整理；
- 历史招标文件样本；
- 业务专家经验；
- 人工复核结果；
- 漏报误报复盘；
- 质疑投诉和整改案例；
- LLM 自动抽取和候选生成。

AI 可以生成候选知识，但不能直接发布为有效知识。

## 4. 核心功能

### 4.1 知识采集

支持上传法规、政策、招标文件、审查报告、复盘材料，并通过 LLM 辅助抽取候选知识。

### 4.2 知识结构化

将非结构化资料转为结构化知识条目，包括：

- 适用地域；
- 适用品类；
- 适用采购方式；
- 适用章节；
- 触发信号；
- 判断规则；
- 排除条件；
- 输出口径。

### 4.3 知识分层管理

按法规层、行业基础层、审查知识点层、风险审查点层、品类场景层、语料样本层、复盘层管理。

### 4.4 知识状态管理

建议状态：

```text
草稿 -> 待复核 -> 试运行 -> 有效 -> 废止
```

不同状态决定是否可驱动正式 AI 审查。

### 4.5 知识发布和版本管理

支持：

- 发布；
- 退回；
- 废止；
- 替代；
- 回滚；
- 版本对比；
- 生效时间和失效时间。

### 4.6 知识适用范围管理

支持按以下维度管理：

- 省份；
- 城市；
- 平台；
- 采购方式；
- 品目；
- 场景；
- 文件章节；
- 预算区间；
- 项目属性。

### 4.7 知识引用关系

支持查看：

- 哪些风险审查点引用了某条法规；
- 哪些审查任务命中了某条知识；
- 哪些人工复盘修改了某条规则；
- 哪些知识更新申请影响某个品类包。

## 5. 省份和品类包设计

产品应采用“全国基础包 + 省份知识包 + 品类审查包 + 场景规则”的组合。

示例：

```text
福建上线物业品目
  -> 全国通用政府采购规则
  -> 福建省政府采购规则
  -> 福建平台规则
  -> 物业管理品类审查包
  -> 福建物业复盘规则
```

```text
四川上线计算机品目
  -> 全国通用政府采购规则
  -> 四川省政府采购规则
  -> 四川平台规则
  -> 计算机设备品类审查包
  -> 四川计算机设备复盘规则
```

## 6. 角色权限

| 角色 | 权限 |
| --- | --- |
| 知识维护人 | 新增和编辑草稿 |
| 业务审查人 | 使用知识、提交复盘和更新申请 |
| 省份管理员 | 管理本省知识包和本地规则 |
| 品类专家 | 复核品类审查包 |
| 法规复核人 | 复核法规依据和效力边界 |
| 知识管理员 | 发布、废止、回滚知识 |
| 系统管理员 | 配置权限、流程和算力资源 |

## 7. 与 LLM + Wiki 的关系

LLM + Wiki 可继续作为知识生产和样板验证工具：

- 快速整理法规；
- 快速形成审查点；
- 快速沉淀复盘；
- 快速验证品类包。

正式产品负责：

- 审批发布；
- 权限隔离；
- 版本控制；
- 结构化调用；
- 指标评估；
- 多省份上线管理。

## 8. 关键指标

- 知识条目数量；
- 有效知识占比；
- 试运行知识转正率；
- 知识命中次数；
- 命中后人工确认率；
- 命中后误报率；
- 知识更新申请通过率；
- 省份知识包覆盖度；
- 品类审查包成熟度。

## 9. 产品经理结论

知识生成管理线是产品的核心壁垒。正式产品不能只做上传资料和搜索，而要支持省份、品类、状态、版本、权限和算力环境下的知识治理，让知识稳定驱动 AI 审查。
