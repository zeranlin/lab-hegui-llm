# 三线闭环总体方案说明书

版本:: 1.0
状态:: 初稿
适用范围:: 政府采购招标文件合规审查知识作业平台

## 1. 文档目的

本文用于说明正式产品的三条主线如何设计，以及三条线如何共同形成政府采购招标文件合规审查的知识闭环。

三条线分别是：

1. 政府采购招标文件审查知识生成管理线；
2. AI 审查主流程线；
3. 人工调整和精确率提升线。

## 2. 总体闭环

产品总体闭环为：

```text
知识生成管理线
  -> AI 审查主流程线
  -> 人工调整和精确率提升线
  -> 回到知识生成管理线
```

业务闭环为：

```text
法规/政策/经验/案例
  -> 结构化知识
  -> 审查规则和风险审查点
  -> 文件画像
  -> 知识路由
  -> 逐章审查
  -> 风险输出
  -> 人工复核
  -> 漏误报复盘
  -> 知识更新申请
  -> 知识发布
  -> 下一轮审查更准
```

## 3. 第一条线：知识生成管理线

### 3.1 定位

知识生成管理线负责管理“系统知道什么、哪些知识可用、谁能改、什么时候生效”。

它不是普通资料库，而是政府采购招标文件合规审查的知识治理中心。

### 3.2 管理对象

- 法规政策；
- 行业基础；
- 审查知识点；
- 风险审查点；
- 风险模式；
- 品类审查包；
- 场景画像；
- 语料样本；
- 提示词；
- 输出模板；
- 知识更新申请；
- 知识版本。

### 3.3 核心功能

- 知识创建；
- 知识分类；
- 元数据管理；
- 适用地域管理；
- 适用品类管理；
- 状态管理；
- 审核发布；
- 版本回滚；
- 知识引用关系；
- 知识调用效果分析。

### 3.4 输出给第二条线的内容

- 可用法规依据；
- 可用审查规则；
- 可用风险审查点；
- 品类审查包；
- 文件画像规则；
- 逐章审查矩阵；
- 风险输出模板；
- AI 审查提示词。

## 4. 第二条线：AI 审查主流程线

### 4.1 定位

AI 审查主流程线负责管理“新文件进来后怎么审、按什么知识审、风险怎么输出”。

它是智能审查工作台，不是自由问答工具。

### 4.2 处理对象

- 待审招标文件；
- 抽取文本；
- 文件章节；
- 项目画像；
- 审查任务；
- 知识路由结果；
- 风险项；
- 审查报告。

### 4.3 标准流程

```text
文件上传
  -> 文件解析
  -> 章节识别
  -> 项目画像
  -> 知识路由
  -> 逐章审查
  -> 风险识别
  -> 风险去重和聚合
  -> 审查结果生成
  -> 提交人工复核
```

### 4.4 风险输出要求

每条风险至少包含：

- 风险标题；
- 风险等级；
- 风险类型；
- 所属章节；
- 原文位置；
- 原文证据；
- 问题说明；
- 关联审查点；
- 审查依据；
- 修改建议；
- 是否需要人工复核；
- 命中的知识版本。

### 4.5 输出给第三条线的内容

- AI 风险清单；
- 未列风险说明；
- 待确认事项；
- 知识命中记录；
- 原文定位；
- AI 置信度；
- 审查任务日志。

## 5. 第三条线：人工调整和精确率提升线

### 5.1 定位

人工调整和精确率提升线负责管理“审查人员如何修改 AI 结果，系统如何从修改中学习”。

它是审查质量提升中心。

### 5.2 管理对象

- 人工确认记录；
- 人工驳回记录；
- 风险修改记录；
- 新增漏报风险；
- 删除误报风险；
- 争议项；
- 复盘记录；
- 知识更新申请；
- 指标统计。

### 5.3 人工操作类型

- 确认风险；
- 驳回风险；
- 修改风险等级；
- 修改风险标题；
- 修改原文定位；
- 修改问题说明；
- 修改审查依据；
- 修改整改建议；
- 合并重复风险；
- 拆分复杂风险；
- 新增漏报风险；
- 标记争议项；
- 标记项目个案。

### 5.4 复盘分类

漏报原因：

- 知识库缺规则；
- 规则有但未召回；
- 项目画像错误；
- 章节识别错误；
- 表格解析失败；
- AI 判断失败；
- 输出口径缺失。

误报原因：

- 规则适用范围错误；
- 排除条件缺失；
- 品类场景边界不清；
- 地方规则适用错误；
- 原文理解错误；
- 风险等级过高；
- 输出表达过度。

### 5.5 回写机制

人工调整后的内容按以下路径处理：

```text
人工调整
  -> 判断是否可复用
  -> 生成复盘记录
  -> 生成知识更新申请
  -> 专家或知识管理员复核
  -> 更新知识层
  -> 进入试运行或有效状态
  -> 后续审查验证效果
```

## 6. 三条线的接口关系

| 来源线 | 输出 | 接收线 | 用途 |
| --- | --- | --- | --- |
| 知识生成管理线 | 有效知识、审查点、模板、提示词 | AI 审查主流程线 | 驱动文件画像、逐章审查和风险输出 |
| AI 审查主流程线 | 风险项、命中记录、待确认事项 | 人工调整线 | 供审查人员复核和修改 |
| 人工调整线 | 漏报、误报、知识更新申请 | 知识生成管理线 | 更新知识库和规则版本 |

## 7. 最小产品闭环

一期 MVP 不需要一次性覆盖所有品类，应优先选择物业管理或信息化设备，跑通以下闭环：

- 建立一个品类审查包；
- 上传一批真实招标文件；
- 完成文件画像；
- 按章节输出风险；
- 人工确认和修改风险；
- 记录漏报和误报；
- 生成知识更新申请；
- 回写风险审查点或排除条件；
- 下一份文件验证改善效果。

## 8. 产品经理判断

三条线不是三个孤立模块，而是一个知识驱动审查系统的三段能力。

第一条线决定 AI 有什么依据，第二条线决定 AI 怎么执行审查，第三条线决定系统能不能越用越准。只有三条线闭环，产品才能从一次性 AI 工具升级为政府采购行业审查能力平台。
