# MVP 版本规划与验收标准

版本:: 1.0
状态:: 初稿
适用范围:: 政府采购招标文件合规审查知识作业平台

## 1. MVP 目标

MVP 的目标不是做全品类、全省份、全流程采购平台，而是验证：

```text
一个省份 + 一个品类 + 一套本地知识包 + 一套本地算力
能否跑通知识生成、AI 审查、人工复核和知识回写闭环。
```

## 2. 推荐 MVP 范围

建议选择以下任一组合：

### 2.1 福建 + 物业管理

适合验证：

- 省份知识包；
- 物业品类审查包；
- 发布前合规审查；
- 人工复盘回写。

### 2.2 四川 + 计算机设备

适合验证：

- 省份知识包；
- 货物类或计算机品类审查包；
- 技术参数和评分风险；
- 本地算力和知识隔离。

### 2.3 深圳 + 物业管理

适合利用当前样板基础，快速形成可演示闭环。

## 3. MVP 必做能力

### 3.1 知识治理

- 全国通用知识包；
- 目标省份知识包；
- 一个品类审查包；
- 风险审查点管理；
- 知识状态；
- 知识更新申请；
- 基础版本管理。

### 3.2 AI 审查

- 文件上传；
- 文本解析；
- 章节识别；
- 项目画像；
- 知识路由；
- 逐章审查；
- 风险输出；
- 审查报告导出。

### 3.3 人工复核

- 确认风险；
- 驳回风险；
- 修改风险；
- 新增漏报；
- 记录误报；
- 生成复盘；
- 发起知识更新申请。

### 3.4 属地化配置

- 租户配置；
- 省份知识空间；
- 本地算力环境；
- 启用品类包；
- 跨省知识隔离；
- 全国知识继承。

## 4. MVP 暂不做

- 不做全省份覆盖；
- 不做全品类覆盖；
- 不做采购交易流程；
- 不做供应商投标辅助；
- 不做自动执法定性；
- 不做复杂知识图谱展示；
- 不做大规模模型训练平台；
- 不做合同履约全生命周期。

## 5. 验收场景

### 5.1 文件画像验收

系统能识别：

- 采购方式；
- 评审方法；
- 采购品目；
- 标的属性；
- 适用地域；
- 是否中小企业政策；
- 是否联合体；
- 是否进口产品；
- 主要章节完整性。

### 5.2 知识路由验收

系统能根据画像调用：

- 全国通用知识；
- 目标省份知识；
- 目标品类审查包；
- 对应章节风险审查点。

### 5.3 风险输出验收

每条风险必须包含：

- 原文位置；
- 原文内容；
- 风险标题；
- 风险等级；
- 问题说明；
- 审查依据；
- 关联审查点；
- 修改建议。

### 5.4 人工复核验收

审查人员能完成：

- 确认；
- 驳回；
- 修改；
- 新增漏报；
- 标记误报；
- 生成复盘；
- 提交知识更新申请。

### 5.5 知识回写验收

系统能完成：

- 从复盘生成知识更新申请；
- 选择目标知识层；
- 选择目标省份和品类；
- 审核通过后进入试运行或有效状态；
- 后续审查任务能调用更新后的知识。

## 6. 指标验收

MVP 应至少统计：

- 文件解析成功率；
- 画像人工修正率；
- AI 风险人工确认率；
- AI 风险驳回率；
- 漏报数量；
- 误报数量；
- 知识命中次数；
- 知识更新申请数量；
- 知识更新申请通过率；
- 单份文件平均审查时长。

## 7. 样本要求

建议准备：

- 目标省份法规政策；
- 目标省份平台规则；
- 目标品类 5 至 10 份真实招标文件；
- 已知风险样本；
- 正常条款样本；
- 人工专家复核样本；
- 知识更新申请样本。

## 8. 里程碑

### 8.1 M0：样板准备

- 完成省份知识包初稿；
- 完成品类审查包初稿；
- 完成样本文件整理；
- 完成 LLM + Wiki 样板验证。

### 8.2 M1：最小审查闭环

- 文件上传解析；
- 项目画像；
- 知识路由；
- 逐章审查；
- 风险输出。

### 8.3 M2：人工复核闭环

- 风险确认和修改；
- 漏报误报复盘；
- 知识更新申请。

### 8.4 M3：知识回写闭环

- 知识审核；
- 试运行发布；
- 后续文件验证。

## 9. 产品经理结论

MVP 的关键不是功能多，而是闭环真。只要一个省份、一个品类、一个算力环境能跑通知识生成、AI 审查、人工复核和知识回写，就证明产品方向成立；之后再按省份和品类复制扩展。
