# 政府采购招标文件合规审查 LLM Wiki

这是一个 Karpathy 风格的 LLM Wiki，用来沉淀政府采购招标文件中的合规审查知识点、风险模式、法规依据和具体项目审查记录。

## 标准结构

- `raw/`：原始材料，不直接编辑。招标文件、法规 PDF、Word、图片、抽取文本都放这里。
- `wiki/`：LLM 可编辑的 Markdown 知识库。
- `AGENTS.md`：智能体操作协议和 wiki 结构。
- `wiki/index.md`：知识库地图。
- `wiki/log.md`：ingest、整理、审查工作的日志。
- `tools/wiki.py`：本地维护命令。

## 标准命令

```bash
./ingest raw/招标文件/example.pdf
./query "本地化"
./lint
```

也可以直接使用 Python 入口：

```bash
python3 tools/wiki.py ingest raw/招标文件/example.pdf
python3 tools/wiki.py query "本地化"
python3 tools/wiki.py lint
```

## 使用方式

1. 将待审招标文件放入 `raw/招标文件/`。
2. 运行 `python3 tools/wiki.py ingest raw/招标文件/文件名` 建立来源笔记。
3. 在 `wiki/40-审查工作台/审查记录/` 复制 `wiki/90-模板/审查记录模板.md` 建立项目审查记录，记录状态默认为 `AI 审查版`。
4. 先做文件画像，再按 `wiki/20-知识点/政府采购逐章审查矩阵.md` 逐章抽取和审查。
5. 每个风险点必须保留：原文证据、问题说明、关联审查点、法规依据、风险等级、修改建议。
6. 新发现的可复用风险，沉淀到 `wiki/25-风险审查点/` 或 `wiki/30-风险库/`；新知识点沉淀到 `wiki/20-知识点/`。

## 目录说明

- `wiki/00-入口/`：总索引、审查流程、知识地图。
- `wiki/10-法规依据/`：法规、部门规章、规范性文件与条文摘录。
- `wiki/20-知识点/`：可复用的审查知识点，按主题组织。
- `wiki/30-风险库/`：风险模式库，面向 LLM 检索和匹配。
- `wiki/40-审查工作台/`：项目审查记录、审查输出。
- `wiki/50-语料与摘录/`：历史招标文件摘录、典型条款样本。
- `wiki/60-提示词/`：LLM 审查提示词、抽取提示词、复核提示词。
- `wiki/90-模板/`：Obsidian 笔记模板。

## 核心原则

- 只依据文件原文和明确法规依据判断，不凭印象下结论。
- 风险点要能回溯到原文位置。
- 结论要区分“明确违规”“高风险”“需进一步确认”“提示优化”。
- 每次审查都要把可复用经验沉淀回知识库。
- 标准审查采用 AI 审查口径：不得读取外部批注、标准答案或 V2 检查结果来反推风险点。
- 外部标注只用于 AI 审查完成后的精确率提升流程，形成独立复盘记录，不能和正式 AI 审查结果混同。
